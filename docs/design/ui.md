# 画面の仕様

実装済みの画面の挙動。コードは `public/app.js`・`public/index.html`・`public/style.css`。国旗・区画の表示と地球の連動は [architecture.md](architecture.md#国旗と地球の連動)。

## 範囲（国・都道府県）

カテゴリの木は 1 つで、国と、その中の区画（都道府県・州）は「範囲（scope）」としてカテゴリの件数・一覧・検索・ピックアップ・HUD の件数・地球儀にかける。範囲は国コード（`jp` `us`…）、区画（`jp-13` `us-ca`…。`sites.region_code` が一致するサイトだけ）、または `all`（全世界）。URL は `/jp/` `/us/` `/all/`、区画は `/jp/13/` `/us/ca/`（カテゴリは従来のクエリ `?category=`、検索は `?q=`）。国だけ分かって区画が NULL のサイトは国の範囲にだけ出る（区画の範囲には出ない）。ルート `/` は既定範囲（日本）として `/jp/` と同じ内容を返す。URL の扱いと理由は [seo.md](seo.md)。

- **切替**: ロゴ下の 1 行に、地球儀（全世界）と国旗のアイコンだけを並べる。国名・地域名は見える文字にしない（アイコンで識別する。#76）。名前は各リンクの `aria-label`（日 `日本 10件` / 英 `Japan, 10 sites`。全世界も同形式。SSR は英語のみ）と `title`（ホバーのツールチップ）にだけ置く。国名は `countries.js` の表、無ければ `Intl.DisplayNames`、最後にコード。国旗 SVG は台湾を含む 14 か国分で、それ以外（と旗の読み込み失敗時）は見える側を 2 文字の国コードで代える（title が出ないスマホ向けに `aria-label` は常に国名）。色は不透明度で薄めず実色で、ライト/ダークとも アイコン・コードは 3:1 以上、件数（11〜12px）は 4.5:1 以上（実測はPR #82）。展開/閉じるで範囲ナビを描き直してもフォーカスは同じ項目（展開ボタンか現在地）に戻す。現在の範囲は不透明度を上げ、下線（暖色）を引き、`aria-current="page"` を付ける。各アイコンの右に範囲内のサイト数は残す（国名が無いので、選ぶ手がかりとして必要）。タップ領域は 32px 以上（スマホは 36px）。選べる国は「サイトが 1 件以上ある国」だけ（`/api/scopes`）。全世界は常に先頭。国は件数の多い順で、7 か国以上は 6 つまで並べ、残りは「⋯」アイコンのボタン（`aria-label`「他の国を表示」、開くと ▴ で「他の国を閉じる」）で開く（現在の範囲が残りにあるときは最初から開く）。各項目は通常のリンク（`<a href="/us/">`）で、修飾キー付き・中クリックはブラウザに任せる。スマホでも折り返して収める。
- **区画（#127、プルダウンは #177 で撤去）**: 範囲ナビに区画（都道府県・州）の選択 UI は無い（国の一覧と地球儀だけ）。区画の範囲は URL `/jp/13/`・`scope=jp-13`・API・集計（0026）として残り、区画へ入る経路は URL 直入り・JS 無効時の SSR リンク・外部リンク・戻る/進むだけ（画面上で区画を選ぶ手段は無い。地球儀の背景クリックも国のみ）。範囲が区画のときは国旗の行でその国に下線（`aria-current="true"`。範囲そのものは `page`）を引く。SSR だけは、JS なしでも・クローラも辿れるよう、サイトのある区画への通常のリンク（`/jp/13/` 形式）を折りたたみ `<details class="region-links">` で国のページ内に出す（サイトの無い区画は出さない。JS が起動すると範囲ナビごと描き直されて消える。JS 有効の環境では `@media (scripting: enabled)` で初期描画から非表示にし、一瞬の表示とナビの高さの縮みを出さない）。HUD は `SITES · JP-13`、タイトルは `MISE — Tokyo, Japan: …` / `… (Tokyo, Japan) — MISE`（ja は `東京都、日本`）。
- **範囲ナビの構造（SSR と JS で同じ）**: 先頭 `MISE_INLINE_SCOPES`（6、`public/countries.js` が正本。`app.js` の `renderScopeNav` と `src/seo.js` の `scopeNavHtml` が共有）か国だけ並べ、残りは `hidden` にして「もっと見る」ボタン（`.scope-more`）の後ろへ。現在の国が残りにあるときは全部開く。SSR と JS 描き直し後の高さを合わせて CLS を出さないため。区画の範囲ではその国の項目に `aria-current="true"` を付けるのも SSR と JS で同じ。「もっと見る」の文言は `countries.js` の `MISE_SCOPE_MORE_WORDS` が正本（SSR は英語固定のため、日本語表示でも JS 起動前の一瞬だけ英語が出る。既存仕様）。実ブラウザでの突き合わせは `node scripts/check-scope-nav-parity.mjs`（README）。JS なし（`scripting: none`）では `hidden` を解いてボタンを隠し、全部の国へ辿れる。
- **地球儀**: 選べる国に点を置き、背景のクリック/タップで範囲を選ぶ（[architecture.md](architecture.md#範囲の選択地球儀)）。国旗リンクで選んだときは地球をその国へ、区画の URL で開いたとき・戻る/進むで区画に戻ったときは `regions.js` の代表点（区画の距離）へ向ける。目印の点は国単位のまま（区画の範囲でもその国の点を強調）。サイト行は、PC ではホバー/フォーカス、スマホでは旗または行のリンク以外のタップで所在地へ向ける。ロゴ・トップ・範囲「全世界」では世界全体の見え方へ即座に戻す。
- **件数**: カテゴリの件数は範囲内だけを数える。範囲内に 0 件のカテゴリも隠さず薄く表示し（`.is-empty`、不透明度 0.6。リンク・補助文字とも背景に対し実測 3.7:1 以上〔ダークのリンクは 5.5:1、ライトのリンクは 4.6:1〕、国ごとに同じ構造に見える）、押せる。国のないサイト（`country_code` が NULL）は全世界にだけ出る。
- **切替時に引き継ぐ状態**: カテゴリ階層は維持する（移動先で 0 件でも同じ階層に留まり、空の案内を出す）。検索語も維持し、結果を新しい範囲で出し直す（URL は `/us/?q=…`）。ピックアップは範囲内から選び直す。HUD は範囲内の掲載数・日別登録数（国の範囲では `SITES · US` のように国コードを添える）。
- **履歴**: 国の切替は `pushState`（区画へは画面から切り替えられない）。戻る/進むで範囲・階層・検索を復元する（区画 `/jp/13/` と国 `/jp/` の行き来も同じ）（`popstate` で範囲が変わるときはそのデータを読んでから復元）。範囲ごとのデータは同じページ内ではキャッシュする。
- ACTIVITY には `scope us` と出る。`prefers-reduced-motion` では切替の遷移（不透明度）を止め、地球は即時に向く。

## カテゴリ階層と検索

検索語は全角・半角を含む空白で区切り、順序に関係なく全ての語を含むサイトに一致する。複数語は各語の部分一致で判定する。

- カテゴリを選ぶと前の階層を置き換え、直下のカテゴリとサイトだけを表示する。パンくずで上位に戻れる。「掲載サイト」の括弧には現在の範囲でそのカテゴリに直接所属するサイト数を表示し、子孫のみのサイトは含めない。0件も表示し、件数が上限付きの場合は `1,000+` と明示する。ページ送り・JS 無効時も同じ件数。
- **トップ画面の子の並び（`.sub`）**: 各トップの下に、そのトップの直下の子の名前を ` / ` 区切りで並べる。各名前は `<span>` で包み `.sub span { white-space: nowrap }` で、名前の途中では改行せず、改行は区切りの ` / ` の位置だけ（SSR と JS で同じ構造）（日英とも。名前に空白や「・」を含むので空白区切りにしない）。子は 4〜17 個あるので、CSS の `line-clamp: 3` で 3 行を超える分を省略記号で切る（全名は DOM に残る）。SSR（`seo.js`）と JS（`app.js`）は同じ区切り。
- **一覧の入れ替えは 200ms のフェード**（カテゴリ移動・パンくず・戻る/進む・範囲切替・検索語の変更）。`document.startViewTransition` があればそれを使い（一覧とその後ろの区切り線・導入文・1200px 未満のコーナーパネルを 1 つの列 `#view-column` にまとめて `view-transition-name: mise-view`。別々にすると新しい位置へ一気に移り、旧一覧の下から完全不透明で見える。ページ全体と地球儀は動かさない）、無ければ `.fade-in`（opacity の CSS アニメ）で同じ見た目にする。View Transitions では、遷移の描画更新の中で新しい画面の最初のページを最大 600ms 待ってから確定し、旧→新を直接つなぐ（時間切れなら行は後から 200ms でフェードイン。非対応ブラウザも行の到着時にフェードイン）。範囲切替（トップ・子カテゴリだけの画面を含む）もフェードする。戻る/進むでは待機中の描画があるので、直後の再描画（`applyLanguage`）は重ねない。列のグループは位置・大きさを補間せず（`animation-name: none`）新しい列の位置に固定し、旧像・新像は列の上端に揃えて（`object-fit: none; object-position: top`）はみ出しを切る。旧像・新像は `animation-fill-mode: both` を明示し、フェード終了後〜遷移終了の間も旧 0 / 新 1 を保つ（グループの一括指定で fill が none に戻ると旧像が不透明で残る）（スクロールした状態から移っても列がヘッダー・検索欄の上をスライドしない）。非対応・同期描画の `.fade-in` は、1200px 以上では一覧側（`#directory` / `#results`）だけにかけ、列内の固定要素を点滅させない（1200px 未満は列ごと）。連打で捨てられた遷移の `ready` / `updateCallbackDone` の拒否も捕捉する。遷移の疑似要素は最前面に描かれるので、固定のピックアップ・コーナーパネルは別の `view-transition-name` にして元の重なり順を保つ。猫は名前を付けない（遷移中に猫の退場で `hidden` になると名前付きの新要素が消えて遷移が skip され、フェードが飛ぶため。ルート像に含まれる）。固定要素の別名は 1200px 以上だけ（それ未満はコーナーパネルが列の一部として一緒にクロスフェードする）。切り出した要素の旧像は即時に消し、二重像にしない。URL（pushState）は遷移の描画を待たず同期で確定し、古い遷移の描画コールバックは、後から別の画面が決まっていたら何もしない。戻る/進むでトップなど一覧の無い画面（ブラウザ標準のスクロール復元）へ戻るときは View Transitions を使わず同期描画にする（復元が古い短い DOM に対して行われて 0 に切り詰められるため）。遷移中は画面全体が止まる（API が遅いと最大 600ms の待機＋200ms のフェード）。クリックは疑似要素に当たるだけで別の要素への誤クリックは起きない。連打は進行中の遷移を `skipTransition()` して上書き。`prefers-reduced-motion: reduce` では即時入れ替え。**対象外**: SSR の初期表示、言語切替の再描画、無限スクロールの追記（追加分はそのまま出る）、申請フォームの開閉。
- 階層は URL の `/<範囲>/?category=<親ID>&category=<子ID>` に反映し、直接開く・リロード・戻る/進むで復元する。日本語名を使う旧 URL は ID に変換し、無効な値はトップに戻す（#114 で消えた旧カテゴリの id もこの無効値で、転送表は持たない。階層は 153 カテゴリ・深さ 3 まで。第3階層も同じ仕組みで開く）。複数カテゴリへの所属と、いま表示している 1 本の階層パスは別の概念。
- 検索は、サーバー側（`/api/sites?q=`）で名前・日英の紹介文・URL・タグ名（日英）を部分一致で絞り込む（全件をブラウザに持たない）。比較は NFKC + 小文字化した `sites.search_text` に対する部分一致なので、大文字小文字・全角半角は区別しない（列の埋め直しは [data-model.md](data-model.md#インデックスと検索用列0018)）。入力は 250ms まとめてから問い合わせる。検索語はタグ名（日本語名・英語名）にも部分一致する（#31 第1段。副作用: 一般語はタグにも当たるぶん q のヒットが広がる（ローカル実測 village 3→179、prefecture 1515→1521、city 794→803。「個人サイト」のようなタグ専用語も当たる）。`export_approved_sql` が同じ語を label_ja と label_en の両方に入れるので search_text に同じ語が重複して入るが、部分一致なので無害。意味検索・マッチ度の表示はしない。チップでの AND 絞り込みは次の「タグで絞り込む」）。3 文字以上の語は FTS5 trigram 索引でも絞り、各語の部分一致を確認する。**ヒット数は上限付き**で数える（`TOTAL_CAP` = 1,000。全件を数えると読み取りがヒット件数に比例して増えるため）: 1,000 を超えるときは一覧の下の状態表示を `該当 1,000+ 件` / `1,000+ matches`（`app.js` の `formatCap`。常に `,` 区切りの `1,000+`）にし、「あと N 件」は出さない（読み込み続けた先で末尾に着いたら `ここまで（全 N 件）`の N は読み込んだ件数で正確）。上限以下なら従来どおり `あと N 件`。タグ絞り込みも同じ（`tag` は `q` と同じく上限付き）。カテゴリ・範囲だけの一覧の総数は集計表から正確に出す。`?q=` で開くと検索結果を表示する。フォームでの検索（確定・250ms の入力デバウンス）も URL に `?q=` を反映する（#99）: カテゴリなどから検索に入る最初の 1 回だけ `pushState`、検索中の語の変更は `replaceState`（入力のたびに履歴を積まない。タグ検索も同じ）。語とタグが空になってカテゴリ一覧へ戻るときは、検索に入った `pushState` が `history.state.searchPushed` の印を残しているので、その項目なら `history.back()` で検索に入る前の項目へ戻す（`replaceState` だと同じカテゴリ URL の項目が 2 つ並び、直後の「戻る」が 1 回空振りする。#102。描画は `popstate` の復元が行う。`back()` 待ちの間に語を入力していなければ二重に描かない）。戻り先は「検索に入った元のページ」（カテゴリとは限らない）。`back()` から `popstate` が届くまでの間は `leavingSearch` を立て、その間の再実行は何もしない（`back()` が 2 回積まれて 2 つ前へ戻るのを防ぐ）。間に入力された語は復元後に検索し直し、`popstate` が 1 秒来なければ安全弁として URL をカテゴリへ戻して一覧を描く（安全弁は `replaceState` なので、その後は旧挙動と同じく同じカテゴリ項目が 2 つ並ぶ。遅れて届いた `popstate` は手前のカテゴリ項目に着地するだけ。縮退ケースとして許容）。検索中に再読込した後の `back()` は `popstate` でなく full page load になり、その間に安全弁が発火しうる（最終的な URL と表示は正しい）。印がない項目（URL 直入り・タグ切替 `toggleTag` の `pushUrl`・範囲選択 `chooseScope`・チップを外して積んだ `?q=` の項目）では URL をカテゴリへ `replaceState` で戻す（履歴は積み増さない）。語を消して `back()` した後も「進む」の先には古い検索項目が残り、進むと検索が戻る（ブラウザ標準の履歴どおり）。検索欄右端の `×` は検索語を消し入力欄にフォーカスを戻す。`×` ボタン（`#clear`）とホームリンクは「検索をやめる操作」として `showDirectory` で `pushState` する（Backspace で全部消す操作とは履歴の扱いが違う。現状は意図的に揃えない）。戻る/進む・再読込・共有で検索語と結果を復元し、検索結果の件数・スクロール位置は検索 URL の履歴項目に保存される（下の「戻る/再読込」）。
- 検索結果・一覧の行の所属欄のカテゴリ経路は階層ごとの個別リンクで、区切り「›」はリンクの外のテキスト（上部のパンくずと同じ構造）。
- カテゴリに所属しないサイトは検索結果（全件・語句検索）に出て、所属欄は「未分類」と表示する。カテゴリのページには出ない。
- 検索欄の下の「推薦」リンクで申請フォーム（推薦・取り下げ・訂正、日英）を開く。送信先と仕様は [operations/requests.md](../operations/requests.md)。「申請は依頼であり、叶うとは限らない」旨を常に表示する。理由・詳細は全種別で必須（入力は空だと送信後に「内容を入力してください」を表示）。連絡先欄は無い。送信ボタンはフォームの右端（高さ 44px 以上）。GitHub Issue への案内は出さない（429 は「しばらくしてからもう一度」だけ）。
  - **フォームが開いている間はカテゴリ一覧（パンくず・カテゴリ）を隠す**（`<html>` の `req-open` クラスで CSS が `#breadcrumbs`・`#categories` を `display:none` にする。再描画されても取り残されない）。サイト一覧・検索結果・範囲ナビ・地球儀はそのまま。閉じる（「推薦」リンクの再押下・Esc）と戻る。
  - フォーカス: 開くとフォームの先頭（種類）へ、リンク・Esc で閉じると「推薦」リンクへ戻す。
  - **画面遷移はフォームを閉じてカテゴリを戻す**: カテゴリ・範囲・ホームのリンク、検索の入力、戻る/進む（`showDirectory`・`showResults` の先頭で閉じる）。送信の受理後・言語切替ではフォームは開いたまま（カテゴリも隠れたまま）。範囲切替では閉じてカテゴリを戻す。隠すのは `display:none` なので、スクリーンリーダーにも読まれない。Esc は送信後など、フォーカスがフォームの外（`body`）にあっても閉じる（送信中のボタンは `disabled` でなく `aria-disabled` にしてフォーカスを保つ）。

## タグで絞り込む（#31）

検索結果と箇条書きのサイト行は上下 16px の間隔で区切る。

結果・一覧・ピックアップの行にあるタグ（`.site-tag`）は押せるリンク。押すと検索バーの右（スマホは下の行）に、取り消せるチップ（`#タグ名 ×`）が付き、検索バーの文字と **AND** で絞り込む。意味検索・マッチ度の並びは別（[ideas/scope-and-search.md](../ideas/scope-and-search.md)）。

- **検索語**: 文字が空ならタグだけの検索（見出しは「#タグ のサイト」）、文字があれば絞り込み（「『文字』の検索結果 #タグ」）。入力欄の文字は押しても消えず、チップがあるあいだに文字を変えても AND のまま絞り直す（250ms まとめて問い合わせ）。
- **外し方**: チップの ×、または結果行の同じタグを再押下（押下中のタグは太字＋色付き、`aria-current="true"`）。複数のタグは AND で、5 個まで（超える分は付かず、検索バーの下に「タグは5個までです。」を 4 秒表示し、HUD にも出す。URL からの分も先頭 5 個）。最後のタグを外して検索語も空なら、カテゴリ一覧に戻る。「カテゴリへ戻る」リンク・ロゴ・カテゴリ移動でもチップは外れる。
- **範囲・カテゴリ**: 範囲とは AND（範囲切替でもチップと検索語は維持）。タグ押下で範囲やカテゴリは変えない。カテゴリとも AND にするのは、**カテゴリ一覧の行**（`#directory-sites`）から最初のタグを押したときだけ（その階層の末端カテゴリ直下のサイトに絞り、URL に `category` を載せる）。**検索結果の行・ピックアップ**から押したときは、カテゴリを開いていても範囲全体のタグ検索で、`category` も URL に載せない。タグが付いたあとに別の行から押しても、最初に決まった絞り込み先は変わらない（タグが無い通常の検索は従来どおり範囲全体）。
- **URL**: `?tag=<タグの日本語名>` を繰り返す（例 `/all/?tag=電子工作&tag=個人サイト`。検索語があれば `&q=`、階層があれば `&category=`）。押すたびに `pushState` で履歴に積み、戻る/進む・再読込・共有で復元する（`restoreLocation`）。ホバーは使わない（スマホはタップでチップが付き、検索バーが画面外なら検索バーが見える位置までスクロール）。チップの名前は押した行から取る。URL から開いたときは最初の結果の到着後に日英の名前へ解決する（それまでは URL の文字）。英語名（`?tag=Electronics`）で来たタグは日本語名に正規化し、URL も日本語名に直す（`replaceState`）。6 個以上のタグ・不正なカテゴリの URL は、切り詰めた形に `replaceState` で正規化する。
- **ピックアップの入れ替えとの競合**: ピックアップは 8 秒ごとに入れ替わるが、停止 UI は設けない（決定）。代わりに、押下（pointerdown）時点で描画中だった要素のタグだけを使う。入れ替え直後 500ms 以内（pick-enter アニメと同じ長さ）の押下と、押下〜離す間に要素が入れ替わった場合は、タグを付けず無視する（別サイトのタグが付かない）。この確認はピックアップ内のタグだけにかける（結果行・一覧行は押した瞬間に効く）。キーボード操作（click の detail が 0）は対象外で常に効く。手動の切替（スワイプ等）との関係は「ピックアップ」節の「手動の切替」。
- **API / SSR**: `/api/sites?tag=`（日本語名か英語名。複数は AND、`q`・`category`・`scope` とも AND。6 個以上・101 文字以上は 400）。SSR（`?tag=` で直接開く）は検索結果と同じ扱いで（6 個以上などで不正な `tag` でも）、先頭ページを本文に出し `noindex,follow`・canonical は範囲トップ（タグ別の索引ページとページ番号は未対応。SSR は `q` を無視するが noindex のため対応しない。クライアントが直後に `q` 込みで描き直す）。
- **チップ・タグの大きさ（#165）**: 見た目の高さは**固定かつ文字サイズ基準（em）**（結果行のタグ `.site-tag` = `1.8em`＝10px で 18px、チップ `.tag-chip` = `calc(30em / 13)`＝13px で 30px。#183 で 15px / 28px から上げた〔低く見えたため〕。`box-sizing: border-box` + `height` + `line-height: 1` + `align-items: center` で枠の中央に置き、文字は `.tag-label` の `text-box: trim-both cap alphabetic` で「大文字高〜ベースライン」だけにして上下の余白をそろえる〔下の「上下センタリングはインク基準で測る」〕）。チップの × は文字でなく SVG（`display: grid; place-items: center`）。最小フォント・文字サイズ拡大・ズームでも枠が文字に追従し、文字が枠線を横切らない。`line-height: normal` のままだと、`system-ui` に無い日本語・絵文字が別フォントにフォールバックして行ボックスが 1px 伸び（実測 ラテンのみ 18px／日本語入り 19px）、タグごとに高さがズレたため。ラテンのみ・日本語のみ・混在・絵文字入りで高さは同一（小数点以下まで）。**押せる範囲は見た目と別**に透明な `::before` で確保する: チップの × は見た目 22px（13px 基準）・押せる範囲 28px 以上、タッチ端末（`pointer: coarse`）は縦 44px 以上・横は隣のチップに食い込まない +5px まで。はみ出す上下 8px はタッチ端末の `.tag-chips` の `padding: 8px 0` と `row-gap: 16px` で確保し、検索欄・「推薦」リンク・隣のチップの見た目の範囲を奪わない。結果行のタグはタッチ端末で押せる範囲 36px（高さ 18px + `::before` が上下 9px ずつ。`::before` の `inset` は padding box 基準で枠線 1px を含まないため、上下は `calc(-9px - 1px)` と枠線分を足す。実測 computed 36px。上下 `margin: 8px 0`、横は枠の外端まで）。長大なタグは `white-space: nowrap` のまま（`overflow: hidden` は押せる範囲の `::before` を切るため付けない。実データの最長は 34 字）。検査は `scripts/e2e-tag-height.mjs`（`npm run test:e2e-tag`。要 `wrangler dev --local` と seed。前提は冒頭。`npm run check` は構文のみ）。`#tag-chips[hidden]` は `display:none` を併記。

## 一覧・検索結果の既定の並び

零細の個人サイトの更新が埋もれないよう、既定は「そのサイト自身の更新日」の新しい順。`ORDER BY bulk_import, COALESCE(source_updated_at, registered_at) DESC, id`（日時が読めない/NULL は末尾。台帳などからの一括投入 `bulk_import=1` は常に通常のサイトの後ろ）。更新日が不明なサイトは mise への登録日で代用する（新規登録を新着扱いにする）。今日登録した更新日不明のサイトは、更新日が数か月前の既存サイトより上に並ぶ。

定義は `src/sites.js` の `SORT_KEYS` に 1 か所だけあり（並びのキーを足すときはここだけ。手順は [data-model.md](data-model.md#インデックスと検索用列0018)）、`/api/sites` と SSR のカテゴリ一覧が共有する。`app.js` は並べ替えず、API の順で追記する（検索結果も同じ並び）。インデックスは `SORT_KEYS` から生成した式を migration に書く。NULL/読めない日時は `DESC` で自然に末尾。ピックアップ（ランダム）は対象外。並び順の切替 UI はない（意味検索・マッチ度とセットで構想: [ideas/scope-and-search.md](../ideas/scope-and-search.md)）。

更新日の取得は [procedures.md](../collection/procedures.md#サイトの更新日の取得)。

## 一覧のページング（エンドレススクロール）

カテゴリ直下のサイト一覧と検索結果は、1 ページ 40 件ずつ（`PAGE_SIZE`。`src/sites.js` と `app.js` で同じ値）。官公庁台帳のように 2000 件規模のカテゴリでも、初回描画は 40 件だけ。

- **追加読み込み**: 一覧の末尾（`#directory-foot` / `#result-foot`）を `IntersectionObserver`（下 600px 手前）で見張り、見えたら `next_cursor` で次を取得して追記する。重複・欠落は、並びが安定ソート（キー + id）でカーソルが複合のため起きない。
- **状態表示**: 読み込み中 / あと N 件（上限付きの総件数のときは `該当 1,000+ 件`）/ 末尾（`ここまで（全 N 件）`。上限付きでも N は正確）を常時出す。失敗時は「再試行」ボタン。`IntersectionObserver` が無い環境は「もっと見る」ボタンで続きを読む。スクリーンリーダー向けの通知（`role="status"`）は末尾到達と失敗のときだけで、1 バッチごとには読み上げない。
- **戻る/再読込**: 読み込み済み件数とスクロール位置を `history.state.mise`（`{key, loaded, y}`）に保存し、戻る/進む/再読込で同じ件数まで（上限なし、100 件ずつ）読み直してから位置を戻す。復元中にユーザーが実際にスクロールしようとしたら（wheel / touchmove / スクロール系のキー: 矢印・PageUp/Down・Home/End・Space。ただし入力欄（input / textarea / select / contenteditable）にフォーカスがあるときのキーは文字入力・カーソル移動なので無視）引き戻さない。タップ・touchstart・pointerdown では打ち切らない（API が遅く復元に数秒かかる間のタップで y=0 が確定していた）。取得に失敗しても復元は捨てず、復元中は保存値を上書きしない（「再試行」で続きから復元する）。画面を移る pushState の直前にも現在の件数と位置を同期で保存する（scroll の遅延保存が遷移に間に合わないため）。`pagehide` での再保存は、最後の保存より後にスクロールしたとき、または保存済みの履歴状態が今の一覧のものでないとき（`history.state.mise.key !== activeList.key`。タグ押下の pushUrl で state が空の新項目ができた直後・検索語変更の `replaceState(history.state)` で古い key が残った場合・`leaveSearchUrl` の `replaceState(null)` 後）だけ（件数だけ増えて key が一致する場合は保存済みの位置が旧件数の範囲内なので対象外）。なお別オリジンへ離れる場合、Chromium では pagehide での保存自体が効かない（離脱時にレイアウトが変わる環境で、直前の正しい位置を縮んだ値で上書きしない。#101: Playwright の `hasTouch` は離脱時に `(pointer: coarse)` が外れて行が縮み、保存 y が約 2000px 小さくなっていた。実機では起きない計測環境の癖）。`history.scrollRestoration` は、カテゴリ・検索の状態を持つ画面（子カテゴリだけの階層や 0 件の一覧も含む）で `manual`（件数とスクロール位置を自前で復元）、トップ・範囲だけのページ（`/`・`/jp/`・`/us/`）では `auto`（ブラウザ標準の復元）にする。履歴の項目ごとの設定なので、画面を描くたびに切り替える。
- **`?page=N` で開いたとき**: 一覧は N ページ目の位置（`page` 指定で取得）から始まり、そこから下へ続く。上には「前のページ」リンクを出す（通常のリンク）。URL はスクロールしても変えない。
- **クロール用ページ番号URL**: SSR は `/<範囲>/?category=…&page=N` で N ページ目を返し、ページ番号リンク（前へ/次へ・先頭・末尾・前後 2 ページ。`#site-pager`）と `rel=prev/next` を出す。JS 起動後は `#site-pager` を隠す。範囲外のページは 404。canonical 等は [seo.md](seo.md)。
- 件数: カテゴリ名横の `(N)` は配下を含む件数（`site_count`）、一覧の総数は `/api/sites` の `total`（直下のサイトの件数。`q`・`tag` は上限付きで `total_capped`、上は「検索」の節）。

## ピックアップ

トップで、掲載サイトから最大 3 件をランダムに選び、1 件ずつ 8 秒ごとに表示する。画面外・非表示タブ・アニメーション軽減設定（`prefers-reduced-motion: reduce`）では自動切替をしない（手動の切替は下の「手動の切替」）（軽減設定では最初の 1 件のまま。リロードで別の 3 件）。一時停止/再開の UI は設けない（kako-jun の指示。WCAG 2.2.2 の停止手段は満たさないことを受容、[decisions.md](../decisions.md)）。入れ替え時、フォーカス中のリンクは新しい行の同位置へ戻し、地球儀の国ホバーのホールドは解除する。ファビコンは一覧と同じものを表示する。将来 NEW や確認可能な更新頻度を選出に使う構想があるが、十分な更新履歴や信頼できる日時が揃うまで使わない。人気や閲覧数は使わない。

### 手動の切替（スワイプ・ドラッグ・左右キー、#113）

- **操作**: ピックアップ（`#picks`）の上を、タッチは横スワイプ、マウスは横ドラッグ、キーボードはピックアップ内のリンクにフォーカスして左右キー（←＝前、→＝次。修飾キー付きは無視）で、自動入れ替えを待たずに切り替える。左へのスワイプ・ドラッグが「次」、右へが「前」。アニメは次が右から、前が左から入る（既存の `pick-enter` の向き違い、500ms）。
- **判定**: 押した点からの横移動が 40px（`SWIPE_MIN_PX`）以上で、かつ横が縦の 1.5 倍（`SWIPE_DOMINANCE`）以上のときだけ。指を離すのを待たず、閾値を超えた瞬間に 1 回だけ切り替える（1 回の操作で 1 組）。条件を満たさない縦優勢・小さな動きは何もしない。`#picks` は `touch-action: pan-y pinch-zoom`（縦スクロールとピンチズームはブラウザに任せ、縦に動いた時点でブラウザがタッチを引き取る＝pointercancel）。判定の対象は主ポインタ（`isPrimary`）だけで、2 本目以降の指が触れたら判定を破棄する（ピンチをスワイプにしない）。マウスは `pointerup`/`pointercancel` を window で受けて後始末し、枠外で離しても状態を残さない。さらに `pointermove` で `buttons===0` なら判定を破棄する（ボタンなしのホバーだけで切り替わらない）。
- **履歴**: 直近に表示した組を最大 5 件（`PICK_HISTORY_MAX`）保持する（自動入れ替えも積む）。前へは履歴を戻る。尽きたら前は何もしない（スワイプのときだけ 180ms・10px の弾み。reduced-motion では出さない）。範囲を切り替えて選び直したら履歴は捨てる。
- **タイマー**: 手動で切り替えたら自動入れ替えの 8 秒を最初から数え直す（直後に勝手に入れ替わらない）。
- **タグ押下との競合**: スワイプ/ドラッグが成立した時点で、押下中のタグの記録（`tagDown`）を捨て、その操作の最後に出る click は `#picks` のキャプチャ段階で止める（タグ・リンク・行のタップ処理に届かない。次の押下か 600ms で解除）。切替で出た新しい行にも既存の 500ms 無視が掛かる。`click` を止めるのは `detail!==0` のときだけ（キーボードの Enter・支援技術由来の click は止めない）。選択範囲の解除（`removeAllRanges`）は、スワイプ成立時に選択が `#picks` 内にあるときだけ。ネイティブなリンクのドラッグ開始（`dragstart`）は、押下から離すまで（`pickDrag` がある間）常に止める。ブラウザは押下中に数 px 動いた時点で `dragstart` を出すため、実質「ピックアップ内でマウスを押している間は常に止める」。トレードオフとして、ピックアップ内リンクのマウスドラッグ（ブックマークバーや新しいタブへ）はできない（スワイプを優先）。代替手段は Cmd/Ctrl/中ボタンのクリック、右クリックのコンテキストメニュー、キーボード（従来どおり）。押下なしの `dragstart` は止めない。#picks の上ではダブルタップズームは効かない（ピンチズームは効く）。リンクのタップ・タグのタップは、動かさない限り従来どおり。
- **reduced-motion**: 自動入れ替えは従来どおり止めたまま、手動の切替は有効（アニメなしで即切替）。
- **アクセシビリティ**: 前後ボタンは設けない。切替のたびに視覚的に隠した `role="status"`（`aria-live` の polite 相当）へ「ピックアップ 2 / 3: サイト名」を入れて伝える（言語切替時は空にして古い言語の文言を残さない）。自動入れ替えでは更新しない（8 秒ごとの読み上げを避ける）。フォーカス中のリンクは新しい行の同位置へ戻す（既存）。
- 検証は `scripts/e2e-pickup-swipe.mjs`（スマホ 390 のタッチ・2 本指・PC 1280 のドラッグと枠外で離すケースとキー・言語切替・reduced-motion）。

## NEW タグ

登録日時（`sites.registered_at`）から 30 日未満のサイトに NEW を付ける（期間は仮。未決）。登録日時が不明なサイト、一括投入（`bulk_import=1`）のサイトには付けない。直近登録のグラフ・ACTIVITY（`/api/activity`）も `bulk_import=1` を数えない。一覧の並びは一括投入を後ろにする。新規 INSERT 時は DB のトリガ（migration 0006）が時刻を記録する。

## HUD

画面幅 1200px 以上で表示する（それ未満は非表示）。

- 左上（SITE INDEX）: D1 の実データから、掲載総数と直近 7 日の日別登録数だけを表示する。日別は連続した横バー 1 行固定で、長さは表示範囲の最大日を 100% として正規化する。0 件の日は幅 0、1 件以上は最小幅 3px。凡例は出さない。登録日が不明なサイトは日別に含めない。内部事情（日付不明の件数など）は表示しない。
- 左下（ACTIVITY）: このブラウザで実際に行ったカテゴリ移動（`cd`）・検索（`search`）・地球操作（`look`）を端末風に表示する。新しい行が下に追加され、最大 5 行。画面内のみで、保存・外部送信しない。シェルを実行する機能ではない。

アクセス数や人気順は使わない。

## 新着と縦ビュー

- カテゴリ一覧の先頭に「新着 / New arrivals」を置く。新着の名前から縦ビューへ入る。いまの範囲（全世界・国・区画）のうち、登録から 30 日未満の通常掲載を、掲載日時が新しい順に表示する。NEW マークと同様、登録日時が不明なサイト、一括投入・未来日時のサイトは対象外。
- 各フォルダの箇条書きには画面右下に「縦で見る」を置く。検索結果とタグ絞り込みでも表示し、検索語・タグを縦ビューと戻り先へ引き継ぐ。画面一つ分より下にスクロールすると、その上に先頭へ戻るボタンが現れ、押すと検索欄へフォーカスする。縦ビューは同じフォルダに直接属するサイトを箇条書きと同じ範囲・順序で表示する。範囲と全階層の `category` を共通の URL に持たせ、縦ビューでは `view=feed` を加える。例: `/jp/13/?category=computing&category=programming&view=feed`。
- 縦ビューの上部は左の戻る矢印と右の検索欄。矢印は直前の同じ箇条書きに戻る。縦ビューを直接開いた場合は、同じ範囲・階層・ページの箇条書きを開く。検索を確定すると同じ範囲の検索結果を表示する。
- カードは j/k・矢印・スワイプ・ボタンで移動する。カードの国・区画に地球儀が向く。文字の下に敷く黒のグラデーションは `feed.css` の `--scrim-alpha`（下端の濃さ）・`--scrim-height` で調整する。
- フォルダへのリンクは SSR とブラウザ描画で揃える。ルート `/` は日本、全世界は `/all/`。縦ビューは `noindex,follow`、canonical は通常の箇条書き。ページ番号付きの箇条書きから切り替えると、そのページの先頭からカードが始まる。縦ビューに続きがあるときは、最後のカードから未表示の最初の行へ移動できる。取得上限と端末内の「見たサイト」については [縦フィードの設計](../ideas/surf-feed.md) を参照。

## ファビコン

自前で取得した 32px の WebP を、サイト固定のキー（`<sha256(site_id) 先頭32桁>.webp`。1 サイト 1 画像・上書き。#163）で配信する（`sites.favicon_path` がキー名、`favicon_v` が表示のバージョン）。未取得・失敗時は何も表示せず、**代替アイコン（頭文字・猫模様など）は作らない**。表示時に第三者のサーバーへ問い合わせない（IP・閲覧の事実・Referer を漏らさない）。取得・更新・R2 への配信は実装済み（[collection/favicons.md](../collection/favicons.md)）。

一覧の各行は 1 行目を「[中点] [ファビコン] サイト名 新規タブボタン NEW 国旗 ホスト名」の順に並べ（`.site-head`。中点・ファビコン・新規タブのアイコン・国旗は、行ボックスの中央でなく「サイト名のベースライン + 大文字高の半分（`.357em`）」の高さにそろえる〔`.site-head` は `align-items: baseline`、中点とファビコンは `transform: translateY(calc(半径 - .357em))`、新規タブと国旗は `vertical-align: calc(.357em - 半径)`。文字サイズ・ズームに追従し、名前が折り返しても 1 行目にそろう。行ボックスの中央にそろえる方式は、DejaVu Sans で文字の見た目の中心と 2.5px ずれた〕）、API の `favicon_url`（`/icon/<k>.webp?v=<favicon_v>`。`favicon_path` と `favicon_v` から Worker が組み立てる。切替前の旧データは `?v=` なしの `/icon/<hash>.webp`）を持つサイトだけ、**サイト名の左に 16px の画像**（32px の元画像の 1/2 でぼけない）を出す（サムネイル #130 とは別物）。**ファビコンはサイト名の左にだけ出る。サイト名より下（説明文・タグ・所属カテゴリ）は、ファビコンの有無にかかわらず常に行の左端から始まり、インデントしない。枠・角丸・縁（box-shadow）・下地（背景色）は付けない**（画像そのままの四角。kako-jun 2026-11-19、[decisions.md](../decisions.md)）。ダークで黒いファビコンは背景に溶けうるが、対策は入れない（手元の 1,878 枚で測った、不透明な画素だけの平均明度が 50 未満の割合は約 4.8%。#166）。画像の場所は読み込み前から確保し（16px 固定）、読み込み後に行がずれない。`favicon_url` が無いサイトは何も出さず、**サイト名の位置はアイコンぶん右にずれない（ある行だけサイト名が右にずれる）**。全行に空きを確保してそろえる案は採用しない（kako-jun 2026-11-19）。画像が 404 などで読めなければ消す。装飾なので `alt=''`・`aria-hidden`。表示時に第三者のサーバーへは一切アクセスしない。`public/icons/` の静的ファイル（従来の `favicon_path` が `/icons/…` の値）は、`favicon_url` が無いときだけ従来どおり表示する。置き場は R2（`public/icons/` は件数に上限があり 10 万件に使えない）。
国旗（`.site-flag img`・`.scope-flag`・フィードの `.f-place img`）もファビコンと同方針で、枠・角丸・影・下地を付けない（2026-11-24 kako-jun #228）。`margin: 1px` は旧 border 1px 分の外形を保つための補正で、枠の代わりではない。フォーカスの outline など操作状態の枠は別で残す。

SSR（JS 無効時の `noscript` 相当の一覧）も同じ構造（`.site-head` に中点・サイト名・国・ホスト名、説明文は次の行）で出す。ファビコンだけは SSR に無い（`favicon_url` は API の値のため）。

カテゴリ画面の子カテゴリ一覧（トップ含む）の見出し行も同じ構造で、`.category > .site-head > [.site-bullet][.site-icon.cat-icon][h2]` と並べる（#182）。中点は `.site-bullet` を共用し、ファビコンの代わりに単色のフォルダ（タブ付きの輪郭）を `.cat-icon` で 16px 枠に出す。絵は CSS の `mask`（インライン data URI の SVG）＋`background: currentColor` で、画像リクエストなし・ライト/ダーク追従・`.is-empty` の薄さにも追従。装飾なので `aria-hidden="true"`。見出し本文の左端は、同じ画面でファビコンがあるサイト行の本文と同じ列に来る（スマホ幅〔450px 以下〕はカテゴリ一覧を 1 列・幅いっぱいにし、サイト行と同じ左端にする。幅 290px 固定・中央寄せは初期プロトタイプ以来の値で、意図の記録は無い）。長い名前は `overflow-wrap: anywhere` で折り返す。子カテゴリ名の並び（`.sub`）は説明文と同様に左端から。SSR（src/seo.js）とクライアント（app.js）は同じクラス構成で、`tests/site-row.test.mjs` が静的に検査する。

**リンク先のホスト名**: サイト名の右（1 行目の最後）に、小さく薄い灰色（ライト #4f7480 ＝白地で 5.07:1）で `hostname`（`https://`・パス・クエリ・ポートは省く。`www.` はそのまま）を添える。href と同じ URL から作り（`public/site-host.js` の 1 本を app.js・縦フィード・SSR が共有。読み込みに失敗しても一覧は出て、ホスト名だけが出ない）、表示するだけで外部へはアクセスしない。URL が不正・http(s) 以外なら出さない。読み上げには出す（`aria-hidden` にしない）。長いホスト名は折り返す（`overflow-wrap: anywhere`。短いホスト名を文字単位に割らない）。**国際化ドメインは安全なラベルだけ Unicode に戻す**: ラベルごとに、(a) 漢字・ひらがな・カタカナ・長音・ラテン・数字・ハイフンだけ、または (b) ラテンと紛らわしくない 1 つの文字体系だけ（ハングル・タイ・アラビア等。キリル・ギリシャ・アルメニアは除く）のときだけ戻し、それ以外のラベルを 1 つでも含むホスト名は**ホスト名全体を punycode のまま**出す（`xn--80ak6aa92e.com` が「аррӏе.com」に見えるような偽装を、本物に見せない。kako-jun 2026-11-19 の「punycode のまま出さない」を、この安全側の例外付きに変更）。**配置はサイト名の直後（同じ行）。スマホで長い名前だと折り返してホスト名が次の行に落ちることがある（既知・受け入れ済み。kako-jun 2026-11-19）**。縦フィードのカードにも、サイト名の下にホスト名を 1 行出す（[ideas/surf-feed.md](../ideas/surf-feed.md)）。

## サムネイル

縦フィード（`?view=feed`）のカードに出す、サイトの最初の画面の縮小画像（幅 320px の横長 WebP。`sites.thumb_path`）。API の `thumb_url`（`/thumb/<k>.webp?v=<撮影時刻由来>`。`<k>` はサイト ID から決まる固定のキー）を同一オリジンの絶対パス（`?v=` 付きを含む）として読み、`thumb_lqip`（極小プレースホルダ）を先にぼかして出して画像が届いたら入れ替える（フィードの試作は既にこの形で読む。`public/feed.js`）。`thumb_url` が無い、または読み込みに失敗したサイトは画像領域を背景色のままにする。読み込みに失敗した場合は LQIP も消す。**取れなかったサイトに、サムネイルとしての代替画像は作らない**（ファビコンと同じ）。撮影・更新は [collection/thumbnails.md](../collection/thumbnails.md)、配信は [architecture.md](architecture.md)。カードの見た目の改善は #52・#160。

**カード内のサムネの見え方**（#173）: サムネの枠 `.f-hero` はカード全面（`top:0; bottom:0`、mask なし）で、画面比率によらず `object-fit: cover`・`object-position: center top` で背景として画面全体を埋める（見切れてよい。見切れる幅は下のパンで見せる）。その上に `.f-scrim` が黒（`rgba(0,0,0,…)`）の縦グラデーションを重ねる: 上端はごく薄く（.28→0）画像を締め、下 82%（`--scrim-height`）から下端 `--scrim-alpha`（.86）まで濃くして（立ち上がりの中間点でも下端の 8 割まで黒を載せ、明るいサムネでも説明文の上端のコントラストを保つ）文字を読ませる。灰色がかった色・backdrop-filter のぼかしは使わない。ぼかし `--thumb-blur` は 1.5px（解像度 320×200 は変えない）。サムネがない・失敗したサイトは `.f-bg`（ファビコン由来の背景）と黒のグラデーションのままで、文字と操作は同じ位置に出る。
**サムネのパン（横往復）**: スマホ幅では cover で左右が見切れるので、**いま画面に出ているカード（`.is-active`。IntersectionObserver の判定）のサムネだけ**を（アニメーション自体は測定済みの全カードにかけ、離れたカードは `animation-play-state: paused` で**止めた位置に留める**。`.is-active` が外れたときにアニメーションごと消すと translate が 0 に戻って画像が飛ぶため。戻ってきたらそこから続きを再生する）、見切れる幅のぶん個別の `translate` プロパティだけで左右にゆっくり往復させる（`transform: scale(1.04)` は基本ルールに残す。片道 `--pan-sec` = 10 秒・`ease-in-out`・`alternate` で端でも滑らかに折り返す＝往復 20 秒。`animation-delay` を片道の半分だけ負にして**中央から始める**ので、カードが表示になった瞬間に画像が飛ばない）。移動量は純粋関数 `MiseFeedLib.panGeometry(枠幅, 枠高, 画像の幅, 画像の高さ)`（`feed-lib.js`）が決め、枠の `--pan-w`（画像の実幅）・`--pan-px`（片側の移動量）で CSS に渡す。見切れ幅が 8px 未満・画像が枠より狭い・値が 0/NaN なら `data-pan` を付けず動かさない。測るのは**カードが表示になったとき・画像が届いたとき・リサイズ時の表示中カード**だけで、読みをまとめてから書く（全カードを測ると強制レイアウトで重い）。`prefers-reduced-motion: reduce` では動かさず中央固定（`@media (prefers-reduced-motion: no-preference)` の中でだけ animation をかける。`tests/feed-view.test.mjs` が守る）。離れたカードと画像の読み込みに失敗したカード（変数も消す）は動かさない。PC 幅でもカード枠（520px）に対して画像が横に広ければ同じく動く。リサイズ・回転のときは、表示中でないカードの `data-pan` と `--pan-w`/`--pan-px` を消す（止まった位置の古い translate と古い幅が残ると、戻ったときに横に帯が出る。次に表示になったとき測り直し、中央から始まる）。`getAnimations()` で数えると 1 枚を超えて running に見えることがあるが、描画されないカードで害は無い。個別の `translate` は Chrome 104+ / Safari 14.1+ で、古いブラウザでは動かず中央固定に安全に劣化する。横向きのスマホ（高さ 500px 以下）は名前・本文の `text-shadow` を少し強める（縦向きの見え方は変えない）。

## アプリとして追加（PWA）

ホーム画面に追加すると standalone（ブラウザの枠なし）で起動する。オフライン時は「オフラインです」だけを表示し、古いカテゴリ・サイトは見せない。タブのファビコンは `<link rel="icon">`（`favicon.ico`・`favicon.svg`）で、ロゴと同じ帯の位置（30/31/57/58/72/73%）の三毛猫模様（橙・クリーム・茶）を塗った `M`（濃色の輪郭付き。外側のクリーム色の縁は付けない）になる（`sites.favicon_path` の各サイトのファビコンとは別物）。ホーム画面アイコンは `public/pwa/` の PNG。仕組みは [architecture.md](architecture.md#pwa)。

### インストール提案バナー

ブラウザ標準のインストール提案（上部のミニバー等）は出さない（`beforeinstallprompt` を握って `preventDefault()`）。代わりに**画面下部**に固定の控えめなバナーを出す: 文言・[インストール]・[あとで]（日英。言語切替に追従、ダークも対応）。幅は最大 560px、モバイルでは左右 12px の余白で折り返し、`safe-area-inset-bottom` を避ける。バナーは本文の流れに入らず、閉じられる。`install.js` の実行前に `beforeinstallprompt` が来た場合は取りこぼす（実際にはまず起きない）。`install.js` が読めない場合（404・ネットワーク・拡張機能のブロック）はバナーを出さないだけで、起動処理には影響しない。Android でキーボードが出ると検索結果に重なることがあるが、閉じられるので許容する。

- [インストール]: 握っておいた `prompt()` を呼び、結果にかかわらずバナーを閉じる。結果が dismissed なら却下扱い。
- [あとで]・却下: **7 日間は出さない**（保存された時刻が未来のときは抑制しない。時計が大きく進んだ後に長期間出なくなるのを避ける）。却下時刻を `localStorage`（`mise-install-dismissed-at`）に残す。読み書きに失敗しても（プライベートモード等）バナーは出て閉じられるが、記憶は残らない。
- 出さない場合: standalone 起動（`display-mode: standalone`・iOS の `navigator.standalone`）。`appinstalled` で消す。`beforeinstallprompt` が来ない iOS Safari などでは何も出さない（手順ヒントも出さない）。
- 抑制判定の純関数と `beforeinstallprompt` の捕捉・保持（`window.MiseInstall.event`）は `public/install.js`（`app.js` より前に読み込む。`tests/install-banner.test.mjs` が検査）。表示と配線は `public/app.js`（宣言は起動処理より前に置く）、実ブラウザ検証は `scripts/e2e-install-banner.mjs`。

## 言語

初期言語は、`localStorage` の `mise-language`（`ja` / `en`）があればそれを最優先し、無ければ `navigator.languages`（なければ `navigator.language`）の先頭が `ja` で始まるときだけ日本語、それ以外は英語（`app.js` の `initialLanguage`）。言語を切り替えると `mise-language` に保存される。サーバー側（SSR・`<html lang>`）は Accept-Language で出し分けず常に英語のまま（同一 URL で言語を変えると SEO 設計（`seo.md` の hreflang・canonical）と CDN キャッシュ（Vary）を壊すため）。判定は `index.html` の `<head>` の同期インラインスクリプトが行い、ja 判定時は `<html lang="ja">` にして `i18n-pending` クラスを付け、翻訳対象（`[data-i18n]`・`#scope-nav`・`#directory`・`#breadcrumbs`）を `visibility:hidden` で初期化まで不可視にする（レイアウトは動かさない）。`app.js` は初回の `applyLanguage()` 後（取得失敗時も）にクラスを外し、保険として 3 秒でも外れる（その時点で `app.js` が未実行なら `<html lang>` は `en` に戻り、`app.js` が遅れて動けば `data-initial-lang` から再び日本語になる）。初期言語の判定は `localStorage` の読み取り失敗（サイトデータのブロック等）と分けて行い、読めなくてもブラウザ言語で判定する。`app.js` の起動直後の静的適用では `<title>` を触らない（SSR の title を保つ）。英語判定ではクラスを付けず挙動は変わらない。サイトの紹介文は `description_en`（英語）と `description_ja` を持ち、英語表示で `description_en` が無いサイトだけ日本語に「(Japanese)」を添える（SSR と `app.js` で同じ扱い）。
**サイト名は言語ごとに持てる**（#167）: `name_ja`・`name_en`（どちらも NULL 可）があれば画面の言語のものを出し、無ければ言語共通の `name`（どの言語でも名前は消えない）。API は `name`（従来）に加えて `name_ja`・`name_en`（無ければ null）を返し、言語はクライアントが選ぶ（`/api/sites` のキャッシュ鍵は URL のみで、言語は URL に入らないため）。`app.js`（一覧・ピックアップ・新しいタブのボタンの `aria-label`・ピックアップの読み上げ）と縦フィード（見出し・頭文字・「サイトを開く」の `aria-label`）が言語切替に追従する。SSR は英語固定のため `name_en ?? name`（日本語名は SSR に出さない。検索・並び・URL・同一サイト判定・集計は `name` に依存しないか、`search_text` に三つとも含める）。ホスト名・ファビコンは名前と無関係。

縦フィードは「サイトを開く」に矢印を添え、隣の ↗ からは常に別タブで開ける。通常のリンクは外部リンク設定に従う。別タブリンクにはサイト名入りの読み上げ名と `noopener noreferrer` を付け、44px 以上の操作領域を確保する。HTTP(S) 以外はどちらも表示しない。

## ロゴ

大文字の太い縦長ゴシック体 `MISE`。三毛猫模様のグラデーション。ホバー・フォーカスで模様の境界がなだらかにぼける（`@property --blur` による補間。`prefers-reduced-motion` では即時。`@property` 非対応のブラウザでは補間されず、ホバーで即時にぼける。`@supports` の分岐はない）。M/S の横伸ばしはインラインスクリプトで初回描画前に適用し、通常幅の瞬間を見せない。

**M/S の横伸ばしと文字間（#152）**: 横伸ばしは M 1.5・S 1.4 の固定倍率（M と S の幅はそろえない。旧実装は S を M と同じ幅にそろえて約 2.4 倍にしたため、S の縦線が M の約 2 倍の太さに見えた。1.4 にすると S の縦に近い部分の太さが M の ±1px に収まる）。文字間は layout 幅（フォントの左右の空きを含む）でなく**インク（実際に塗られる範囲）基準**で、隣り合う 2 文字の「行ごとのインク間隔の平均」が 17px になるよう margin を逆算し、インク全体が中央に来るよう両端の margin も補正する。外接（一番出っ張った点どうしの隙間）でなく平均にするのは、S の曲線が上下で引っ込み、外接でそろえると S の両隣だけ見た目が広くなるため。各文字のインクは canvas に同じフォントで描いて行ごとに左右端を取る（計算は純関数 `__miseLogoLayout`、テストは `tests/logo-layout.test.mjs`、実測は `scripts/e2e-logo-ink.mjs`）。JS が動かない・測定に失敗したときは、`style.css` の M/S の倍率と margin が効く（Anton が読み込まれた前提の px 値で、実測では平均インク間隔 17.3 / 17.5 / 16.3px、インク全幅 158px、中央寄せ。JS 版との差は ±1px 程度。通常はインラインの値が上書きする）。測定は失敗（幅 0・canvas が使えない・フォント指定が効かず既定の 10px sans-serif に落ちた・例外）すると、測る前の inline 値に戻して CSS の値を効かせる。canvas の font には weight 1000 を指定するが、実機の Safari/Firefox では未確認（受け付けなければ測定側で検知して CSS の値に戻す）。OG 画像（`public/og/mise-og.svg`）は文字を path にした別の絵で、この倍率とは連動しない。タイトル下に発音記号 `/ˈmiːseɪ/` を小さく出す。

書体は環境で変わらないよう自己ホストする（`public/fonts/`、`font-display: block` で代替書体を見せない）。ロゴは Anton（SIL OFL、`MISE` の 4 文字だけにサブセット化した woff2）、発音記号は Noto Serif Italic（OFL、`/ˈmiːseɪ/` の文字だけ。Lora は ˈ ː を持たないため不採用）。従来の `Impact` などは font-family の後ろにフォールバックとして残す。ロゴの woff2 は `<link rel=preload>` で先読みし、ロゴの文字の実測（幅とインク）は `document.fonts.load` の完了後に行う（失敗しても測定して表示する）。woff2 が 2.5 秒以内に届かない低速回線では、そこで見切って現在の書体で先に測って横伸ばしを済ませ（Chromium は block を約 3 秒で打ち切り代替書体を出すため）、到着後にもう一度測り直す。ライセンス全文は `public/licenses/`。woff2 は `uv run --with fonttools --with brotli python3 -m fontTools.subset <ttf> --text=<文字> --flavor=woff2 --layout-features='*' --name-IDs='*'` で作る（Noto Serif は先に `fontTools.varLib.instancer` で `wght=400 wdth=100` に固定）。書体を差し替えるときは woff2 のファイル名のバージョン（`-v1`）を上げる（`_headers` で immutable の長期キャッシュ）。

## 上下センタリングはインク基準で測る（#183）

枠・旗・アイコンの中で文字が「上下中央」かは、**ボックス（`getBoundingClientRect`）でなく、実際に塗られた画素（文字のインク）で測る**。ボックスの中央に行ボックスを置いても、行ボックスはフォントの ascent/descent（と日本語・絵文字のフォールバック）で上下の余白が非対称なので、描かれる文字は中央からずれる（実測: DejaVu Sans で `.site-tag` の文字が枠の上端 0〜1.5px・下端 3〜4px、中点が文字の中心より 2.5px 上〔行ボックス中央方式〕。Noto Sans では ±0.5px に収まって見えるため、このマシンの既定フォントだけでは見逃す）。

- **測定**: `scripts/ink/measure-ink.mjs`（`scripts/ink/seed.sql` をローカル D1 に入れ、`wrangler dev --local --persist-to <dir>` を立てて実行。手順は冒頭のコメント）。対象だけを白地・黒で描いて deviceScaleFactor 4 で撮り、インクの上端・下端を取る。枠の中の文字は「枠の内側（border の内側）の上端・下端までの距離」と「インク中心 − 枠中心」、旗・中点・アイコンと文字は「相手の上下中心と文字の先頭 1 文字のインク中心の差」。許容は **±0.5px**（CSS px。ディセンダーのある字・絵文字は枠にインクが 1px 未満まで迫らないことだけ見る）。PC1280 / スマホ390 × ja / en（色は白地・黒に固定して描くのでライト/ダークで値は同じ。既定はライトだけ、`INK_BOTH_THEMES=1` で両方）。場面ごとに期待するグループが 0 件なら失敗にする（縦フィードのパネルは `feed-panel` の場面でクリックして開いてから測る）。範囲ナビの旗+件数など「枠のない行内リンク」（推薦リンク）は対象外。`INK_FONT="DejaVu Sans"` のようにフォントを替えて再測定できる（利用者の OS フォントでの崩れの再現）。終了コードは strict な行の許容外があれば 1。
- **直し方（構造で）**: 文字が主役の枠は、`align-items: center`（または固定高のボタンの UA 中央寄せ）に加えて、文字を `text-box: trim-both cap alphabetic`（Chromium 133+・Safari 18.2+）で「大文字高〜ベースライン」だけにする。上下の余白は `padding`（em 基準）か固定 `height` で作り、行ボックスの余白に頼らない。非対応の古いブラウザ（Chrome <133・Safari <18.2・対応前の Firefox。Firefox 160 は対応）では trim されず、従来の `line-height: 1` 中央のまま劣化するだけで壊れない。**`text-box` を前提にした em の `padding` は `@supports (text-box: trim-both cap alphabetic)` の中だけに入れる**（既定は従来の padding。非対応で行ボックス + padding が二重に膨らまない。非対応相当で寸法を測ると main と同じ: 縦フィードのバー PC 99px・スマホ 127px、`.f-directory` 33px、`.f-open` 40px、`about-logo` 42px）。旗・中点・アイコン + 文字は、文字のベースラインから「大文字高の半分（`.357em`）」の高さにそろえる（上の一覧の行の説明）。行ボックスの中央にそろえる方式と、`vertical-align` の個別の数値は使わない。記号は字形がフォントで変わるので文字でなく SVG（`◐`・チップの ×）にし、`display: block; margin: auto` で中央に置く。絵柄が箱の中で偏っているアイコンは `viewBox` をずらして補正する（検索アイコン・外部リンクアイコン）。
- 旗の県名、別タブの SVG、フィード入口、送信ボタンは、`text-box` 対応時にインクの実測に基づく 1px 未満の位置補正を行う。文字や図形だけを動かし、枠とタップ領域の寸法は維持する。
- **ネイティブの `<input>` / `<select>`** は `text-box` が効かず UA が文字を置く。測定値で ±1px 未満に収まるものは許容（上記の表のとおり別扱い）。
- **残る誤差**: かな・数字だけの短いラベルは字形の高さが漢字・大文字と違うため、同じ trim でもインク中心が 0.5〜0.65px ずれることがある。古いブラウザ（`text-box` 非対応）は上の「直し方」のとおり従来の寸法・従来の中央寄せ。

## アクセシビリティ

- 見出し: ページ先頭に視覚的に隠した `<h1>`（言語に合わせて翻訳）。パンくずは `<nav>`、フッタのリンク列（About・作者のサイト・GitHub）も `<nav>`（`aria-label` は作者に限らない中立の「Links / リンク」）。`aria-label` は言語切替で `data-i18n-label` により日英が切り替わる。
- 検索バー: 幅 700px 以下ではコンテンツ幅いっぱい（最大 480px）に広げ、701px 以上は従来どおり幅 280px（700→701px の段差は breakpoint として許容）。タッチ端末（`pointer: coarse`）は横向きなど幅に関わらず高さ 44px 以上・文字 16px（iOS Safari が focus でズームしない下限）。キーボード表示時の位置（visualViewport）と実 iOS は未確認。
- 検索結果のライブ領域は `#result-title` だけ（1 文字ごとの再描画で全リストを読み上げさせない）。
- 外部リンク設定ボタン（`#external-toggle`）の状態は、不透明度でなくリング（押下時）とドットで示す。色は白背景で 4.95:1、ダークで約 12:1（実測）。操作ボタンのホバーは不透明度でなく背景の淡い色で示す。
- サイトのリンク右の「別タブで開く」ボタン（`a.site-newtab`、枠・背景なしの ↗ アイコン）は外部リンク設定がオフの間だけ出す（オンなら全リンクが別タブなので `hidden`）。トグル切替で即時に出し入れし、描画時にも現在値で初期化するのでページング・再検索後も一致する。`target=_blank rel="noopener noreferrer"`、`aria-label`/`title` はサイト名入りで「<サイト名> を新しいタブで開く / Open <site> in new tab」（Issue の固定文言にサイト名を前置。スクリーンリーダーで各ボタンを区別するため）。タップ領域は 32px（透明な余白。縦だけ負マージンで行高を増やさず、`position:relative; z-index:1` で後続の説明文より前面に出して実際に押せる範囲を 32px 確保。右は負マージンにせず旗 `.site-place` と重ねない）、hover/focus-visible は色の変化とアウトラインで示す。地球儀の hover は行全体が対象なのでボタン上でも通常のリンクと同じ扱い（タップでは行のタップ移動から除外）。
- サイトの URL は `http:` / `https:` だけをリンクにする（それ以外はテキストのみ）。
- 英語表示で日本語の紹介文を出すときは、その段落に `lang="ja"` を付ける。
