# 画面の仕様

実装済みの画面の挙動。コードは `public/app.js`・`public/index.html`・`public/style.css`。国旗・区画の表示と地球の連動は [architecture.md](architecture.md#国旗と地球の連動)。

## 範囲（国）

カテゴリの木は 1 つで、国は「範囲（scope）」としてカテゴリの件数・一覧・検索・ピックアップ・HUD の件数・地球儀にかける。範囲は国コード（`jp` `us`…）または `all`（全世界）。URL は `/jp/` `/us/` `/all/`（カテゴリは従来のクエリ `?category=`、検索は `?q=`）。ルート `/` は既定範囲（日本）として `/jp/` と同じ内容を返す。URL の扱いと理由は [seo.md](seo.md)。

- **切替**: ロゴ下の 1 行に、地球儀（全世界）と国旗のアイコンだけを並べる。国名・地域名は見える文字にしない（アイコンで識別する。#76）。名前は各リンクの `aria-label`（日 `日本 10件` / 英 `Japan, 10 sites`。全世界も同形式。SSR は英語のみ）と `title`（ホバーのツールチップ）にだけ置く。国名は `countries.js` の表、無ければ `Intl.DisplayNames`、最後にコード。国旗 SVG は 13 か国分しか無く、それ以外（と旗の読み込み失敗時）は見える側を 2 文字の国コードで代える（title が出ないスマホ向けに `aria-label` は常に国名）。色は不透明度で薄めず実色で、ライト/ダークとも アイコン・コードは 3:1 以上、件数（11〜12px）は 4.5:1 以上（実測はPR #82）。展開/閉じるで範囲ナビを描き直してもフォーカスは同じ項目（展開ボタンか現在地）に戻す。現在の範囲は不透明度を上げ、下線（暖色）を引き、`aria-current="page"` を付ける。各アイコンの右に範囲内のサイト数は残す（国名が無いので、選ぶ手がかりとして必要）。タップ領域は 32px 以上（スマホは 36px）。選べる国は「サイトが 1 件以上ある国」だけ（`/api/scopes`）。全世界は常に先頭。国は件数の多い順で、7 か国以上は 6 つまで並べ、残りは「⋯」アイコンのボタン（`aria-label`「他の国を表示」、開くと ▴ で「他の国を閉じる」）で開く（現在の範囲が残りにあるときは最初から開く）。各項目は通常のリンク（`<a href="/us/">`）で、修飾キー付き・中クリックはブラウザに任せる。スマホでも折り返して収める。
- **地球儀**: 選べる国に点を置き、背景のクリック/タップで範囲を選ぶ（[architecture.md](architecture.md#範囲の選択地球儀)）。国旗リンクで選んだときは地球をその国へ向ける。サイト行は、PC ではホバー/フォーカス、スマホでは旗または行のリンク以外のタップで所在地へ向ける。ロゴ・トップ・範囲「全世界」では世界全体の見え方へ即座に戻す。
- **件数**: カテゴリの件数は範囲内だけを数える。範囲内に 0 件のカテゴリも隠さず薄く表示し（`.is-empty`、不透明度 0.6。リンク・補助文字とも背景に対し実測 3.7:1 以上〔ダークのリンクは 5.5:1、ライトのリンクは 4.6:1〕、国ごとに同じ構造に見える）、押せる。国のないサイト（`country_code` が NULL）は全世界にだけ出る。
- **切替時に引き継ぐ状態**: カテゴリ階層は維持する（移動先で 0 件でも同じ階層に留まり、空の案内を出す）。検索語も維持し、結果を新しい範囲で出し直す（URL は `/us/?q=…`）。ピックアップは範囲内から選び直す。HUD は範囲内の掲載数・日別登録数（国の範囲では `SITES · US` のように国コードを添える）。
- **履歴**: 切替は `pushState`。戻る/進むで範囲・階層・検索を復元する（`popstate` で範囲が変わるときはそのデータを読んでから復元）。範囲ごとのデータは同じページ内ではキャッシュする。
- ACTIVITY には `scope us` と出る。`prefers-reduced-motion` では切替の遷移（不透明度）を止め、地球は即時に向く。

## カテゴリ階層と検索

- カテゴリを選ぶと前の階層を置き換え、直下のカテゴリとサイトだけを表示する。パンくずで上位に戻れる。
- **一覧の入れ替えは 200ms のフェード**（カテゴリ移動・パンくず・戻る/進む・範囲切替・検索語の変更）。`document.startViewTransition` があればそれを使い（一覧とその後ろの区切り線・導入文・1200px 未満のコーナーパネルを 1 つの列 `#view-column` にまとめて `view-transition-name: mise-view`。別々にすると新しい位置へ一気に移り、旧一覧の下から完全不透明で見える。ページ全体と地球儀は動かさない）、無ければ `.fade-in`（opacity の CSS アニメ）で同じ見た目にする。View Transitions では、遷移の描画更新の中で新しい画面の最初のページを最大 600ms 待ってから確定し、旧→新を直接つなぐ（時間切れなら行は後から 200ms でフェードイン。非対応ブラウザも行の到着時にフェードイン）。範囲切替（トップ・子カテゴリだけの画面を含む）もフェードする。戻る/進むでは待機中の描画があるので、直後の再描画（`applyLanguage`）は重ねない。列のグループは位置・大きさを補間せず（`animation-name: none`）新しい列の位置に固定し、旧像・新像は列の上端に揃えて（`object-fit: none; object-position: top`）はみ出しを切る。旧像・新像は `animation-fill-mode: both` を明示し、フェード終了後〜遷移終了の間も旧 0 / 新 1 を保つ（グループの一括指定で fill が none に戻ると旧像が不透明で残る）（スクロールした状態から移っても列がヘッダー・検索欄の上をスライドしない）。非対応・同期描画の `.fade-in` は、1200px 以上では一覧側（`#directory` / `#results`）だけにかけ、列内の固定要素を点滅させない（1200px 未満は列ごと）。連打で捨てられた遷移の `ready` / `updateCallbackDone` の拒否も捕捉する。遷移の疑似要素は最前面に描かれるので、固定のピックアップ・コーナーパネルは別の `view-transition-name` にして元の重なり順を保つ。猫は名前を付けない（遷移中に猫の退場で `hidden` になると名前付きの新要素が消えて遷移が skip され、フェードが飛ぶため。ルート像に含まれる）。固定要素の別名は 1200px 以上だけ（それ未満はコーナーパネルが列の一部として一緒にクロスフェードする）。切り出した要素の旧像は即時に消し、二重像にしない。URL（pushState）は遷移の描画を待たず同期で確定し、古い遷移の描画コールバックは、後から別の画面が決まっていたら何もしない。戻る/進むでトップなど一覧の無い画面（ブラウザ標準のスクロール復元）へ戻るときは View Transitions を使わず同期描画にする（復元が古い短い DOM に対して行われて 0 に切り詰められるため）。遷移中は画面全体が止まる（API が遅いと最大 600ms の待機＋200ms のフェード）。クリックは疑似要素に当たるだけで別の要素への誤クリックは起きない。連打は進行中の遷移を `skipTransition()` して上書き。`prefers-reduced-motion: reduce` では即時入れ替え。**対象外**: SSR の初期表示、言語切替の再描画、無限スクロールの追記（追加分はそのまま出る）、申請フォームの開閉。
- 階層は URL の `/<範囲>/?category=<親ID>&category=<子ID>` に反映し、直接開く・リロード・戻る/進むで復元する。日本語名を使う旧 URL は ID に変換し、無効な値はトップに戻す。複数カテゴリへの所属と、いま表示している 1 本の階層パスは別の概念。
- 検索は、サーバー側（`/api/sites?q=`）で名前・日英の紹介文・URL を部分一致で絞り込む（全件をブラウザに持たない）。比較は NFKC + 小文字化した `sites.search_text` に対する部分一致なので、大文字小文字・全角半角は区別しない（列の埋め直しは [data-model.md](data-model.md#インデックスと検索用列0018)）。入力は 250ms まとめてから問い合わせる。検索語はタグ名には一致しない（タグでの絞り込みは次の「タグで絞り込む」）。全文検索のインデックスはない。`?q=` で開くと検索結果を表示する。フォームでの検索（確定・250ms の入力デバウンス）も URL に `?q=` を反映する（#99）: カテゴリなどから検索に入る最初の 1 回だけ `pushState`、検索中の語の変更は `replaceState`（入力のたびに履歴を積まない。タグ検索も同じ）。語とタグが空になってカテゴリ一覧へ戻るときは URL もカテゴリへ `replaceState` で戻す。戻る/進む・再読込・共有で検索語と結果を復元し、検索結果の件数・スクロール位置は検索 URL の履歴項目に保存される（下の「戻る/再読込」）。
- カテゴリに所属しないサイトは検索結果（全件・語句検索）に出て、所属欄は「未分類」と表示する。カテゴリのページには出ない。
- 検索欄の下の「推薦」リンクで申請フォーム（推薦・取り下げ・訂正、日英）を開く。送信先と仕様は [operations/requests.md](../operations/requests.md)。「申請は依頼であり、叶うとは限らない」旨を常に表示する。理由・詳細は全種別で必須（入力は空だと送信後に「内容を入力してください」を表示）。連絡先欄は無い。送信ボタンはフォームの右端（高さ 44px 以上）。GitHub Issue への案内は出さない（429 は「しばらくしてからもう一度」だけ）。
  - **フォームが開いている間はカテゴリ一覧（パンくず・カテゴリ）を隠す**（`<html>` の `req-open` クラスで CSS が `#breadcrumbs`・`#categories` を `display:none` にする。再描画されても取り残されない）。サイト一覧・検索結果・範囲ナビ・地球儀はそのまま。閉じる（「推薦」リンクの再押下・Esc）と戻る。
  - フォーカス: 開くとフォームの先頭（種類）へ、リンク・Esc で閉じると「推薦」リンクへ戻す。
  - **画面遷移はフォームを閉じてカテゴリを戻す**: カテゴリ・範囲・ホームのリンク、検索の入力、戻る/進む（`showDirectory`・`showResults` の先頭で閉じる）。送信の受理後・言語切替ではフォームは開いたまま（カテゴリも隠れたまま）。範囲切替では閉じてカテゴリを戻す。隠すのは `display:none` なので、スクリーンリーダーにも読まれない。Esc は送信後など、フォーカスがフォームの外（`body`）にあっても閉じる（送信中のボタンは `disabled` でなく `aria-disabled` にしてフォーカスを保つ）。

## タグで絞り込む（#31）

結果・一覧・ピックアップの行にあるタグ（`.site-tag`）は押せるリンク。押すと検索バーの右（スマホは下の行）に、取り消せるチップ（`#タグ名 ×`）が付き、検索バーの文字と **AND** で絞り込む。意味検索・マッチ度の並びは別（[ideas/scope-and-search.md](../ideas/scope-and-search.md)）。

- **検索語**: 文字が空ならタグだけの検索（見出しは「#タグ のサイト」）、文字があれば絞り込み（「『文字』の検索結果 #タグ」）。入力欄の文字は押しても消えず、チップがあるあいだに文字を変えても AND のまま絞り直す（250ms まとめて問い合わせ）。
- **外し方**: チップの ×、または結果行の同じタグを再押下（押下中のタグは太字＋色付き、`aria-current="true"`）。複数のタグは AND で、5 個まで（超える分は付かず、検索バーの下に「タグは5個までです。」を 4 秒表示し、HUD にも出す。URL からの分も先頭 5 個）。最後のタグを外して検索語も空なら、カテゴリ一覧に戻る。「カテゴリへ戻る」リンク・ロゴ・カテゴリ移動でもチップは外れる。
- **範囲・カテゴリ**: 範囲とは AND（範囲切替でもチップと検索語は維持）。タグ押下で範囲やカテゴリは変えない。カテゴリとも AND にするのは、**カテゴリ一覧の行**（`#directory-sites`）から最初のタグを押したときだけ（その階層の末端カテゴリ直下のサイトに絞り、URL に `category` を載せる）。**検索結果の行・ピックアップ**から押したときは、カテゴリを開いていても範囲全体のタグ検索で、`category` も URL に載せない。タグが付いたあとに別の行から押しても、最初に決まった絞り込み先は変わらない（タグが無い通常の検索は従来どおり範囲全体）。
- **URL**: `?tag=<タグの日本語名>` を繰り返す（例 `/all/?tag=電子工作&tag=個人サイト`。検索語があれば `&q=`、階層があれば `&category=`）。押すたびに `pushState` で履歴に積み、戻る/進む・再読込・共有で復元する（`restoreLocation`）。ホバーは使わない（スマホはタップでチップが付き、検索バーが画面外なら検索バーが見える位置までスクロール）。チップの名前は押した行から取る。URL から開いたときは最初の結果の到着後に日英の名前へ解決する（それまでは URL の文字）。英語名（`?tag=Electronics`）で来たタグは日本語名に正規化し、URL も日本語名に直す（`replaceState`）。6 個以上のタグ・不正なカテゴリの URL は、切り詰めた形に `replaceState` で正規化する。
- **ピックアップの入れ替えとの競合**: ピックアップは 8 秒ごとに入れ替わるが、停止 UI は設けない（決定）。代わりに、押下（pointerdown）時点で描画中だった要素のタグだけを使う。入れ替え直後 500ms 以内（pick-enter アニメと同じ長さ）の押下と、押下〜離す間に要素が入れ替わった場合は、タグを付けず無視する（別サイトのタグが付かない）。この確認はピックアップ内のタグだけにかける（結果行・一覧行は押した瞬間に効く）。キーボード操作（click の detail が 0）は対象外で常に効く。
- **API / SSR**: `/api/sites?tag=`（日本語名か英語名。複数は AND、`q`・`category`・`scope` とも AND。6 個以上・101 文字以上は 400）。SSR（`?tag=` で直接開く）は検索結果と同じ扱いで（6 個以上などで不正な `tag` でも）、先頭ページを本文に出し `noindex,follow`・canonical は範囲トップ（タグ別の索引ページとページ番号は未対応。SSR は `q` を無視するが noindex のため対応しない。クライアントが直後に `q` 込みで描き直す）。
- **チップ・タグの大きさ**: チップの × は 28px 以上、タッチ端末（`pointer: coarse`）は 44px 以上。結果行のタグはタッチ端末で高さ 32px 以上。`#tag-chips[hidden]` は `display:none` を併記。

## 一覧・検索結果の既定の並び

零細の個人サイトの更新が埋もれないよう、既定は「そのサイト自身の更新日」の新しい順。`ORDER BY bulk_import, COALESCE(source_updated_at, registered_at) DESC, id`（日時が読めない/NULL は末尾。台帳などからの一括投入 `bulk_import=1` は常に通常のサイトの後ろ）。更新日が不明なサイトは mise への登録日で代用する（新規登録を新着扱いにする）。今日登録した更新日不明のサイトは、更新日が数か月前の既存サイトより上に並ぶ。

定義は `src/sites.js` の `SORT_KEYS` に 1 か所だけあり（並びのキーを足すときはここだけ。手順は [data-model.md](data-model.md#インデックスと検索用列0018)）、`/api/sites` と SSR のカテゴリ一覧が共有する。`app.js` は並べ替えず、API の順で追記する（検索結果も同じ並び）。インデックスは `SORT_KEYS` から生成した式を migration に書く。NULL/読めない日時は `DESC` で自然に末尾。ピックアップ（ランダム）は対象外。並び順の切替 UI はない（意味検索・マッチ度とセットで構想: [ideas/scope-and-search.md](../ideas/scope-and-search.md)）。

更新日の取得は [procedures.md](../collection/procedures.md#サイトの更新日の取得)。

## 一覧のページング（エンドレススクロール）

カテゴリ直下のサイト一覧と検索結果は、1 ページ 40 件ずつ（`PAGE_SIZE`。`src/sites.js` と `app.js` で同じ値）。官公庁台帳のように 2000 件規模のカテゴリでも、初回描画は 40 件だけ。

- **追加読み込み**: 一覧の末尾（`#directory-foot` / `#result-foot`）を `IntersectionObserver`（下 600px 手前）で見張り、見えたら `next_cursor` で次を取得して追記する。重複・欠落は、並びが安定ソート（キー + id）でカーソルが複合のため起きない。
- **状態表示**: 読み込み中 / あと N 件 / 末尾（`ここまで（全 N 件）`）を常時出す。失敗時は「再試行」ボタン。`IntersectionObserver` が無い環境は「もっと見る」ボタンで続きを読む。スクリーンリーダー向けの通知（`role="status"`）は末尾到達と失敗のときだけで、1 バッチごとには読み上げない。
- **戻る/再読込**: 読み込み済み件数とスクロール位置を `history.state.mise`（`{key, loaded, y}`）に保存し、戻る/進む/再読込で同じ件数まで（上限なし、100 件ずつ）読み直してから位置を戻す。復元中にユーザーが実際にスクロールしようとしたら（wheel / touchmove / スクロール系のキー: 矢印・PageUp/Down・Home/End・Space。ただし入力欄（input / textarea / select / contenteditable）にフォーカスがあるときのキーは文字入力・カーソル移動なので無視）引き戻さない。タップ・touchstart・pointerdown では打ち切らない（API が遅く復元に数秒かかる間のタップで y=0 が確定していた）。取得に失敗しても復元は捨てず、復元中は保存値を上書きしない（「再試行」で続きから復元する）。画面を移る pushState の直前にも現在の件数と位置を同期で保存する（scroll の遅延保存が遷移に間に合わないため）。`pagehide` での再保存は、最後の保存より後にスクロールしたとき、または保存済みの履歴状態が今の一覧のものでないとき（`history.state.mise.key !== activeList.key`。タグ押下の pushUrl で state が空の新項目ができた直後・検索語変更の `replaceState(history.state)` で古い key が残った場合・`leaveSearchUrl` の `replaceState(null)` 後）だけ（件数だけ増えて key が一致する場合は保存済みの位置が旧件数の範囲内なので対象外）。なお別オリジンへ離れる場合、Chromium では pagehide での保存自体が効かない（離脱時にレイアウトが変わる環境で、直前の正しい位置を縮んだ値で上書きしない。#101: Playwright の `hasTouch` は離脱時に `(pointer: coarse)` が外れて行が縮み、保存 y が約 2000px 小さくなっていた。実機では起きない計測環境の癖）。`history.scrollRestoration` は、カテゴリ・検索の状態を持つ画面（子カテゴリだけの階層や 0 件の一覧も含む）で `manual`（件数とスクロール位置を自前で復元）、トップ・範囲だけのページ（`/`・`/jp/`・`/us/`）では `auto`（ブラウザ標準の復元）にする。履歴の項目ごとの設定なので、画面を描くたびに切り替える。
- **`?page=N` で開いたとき**: 一覧は N ページ目の位置（`page` 指定で取得）から始まり、そこから下へ続く。上には「前のページ」リンクを出す（通常のリンク）。URL はスクロールしても変えない。
- **クロール用ページ番号URL**: SSR は `/<範囲>/?category=…&page=N` で N ページ目を返し、ページ番号リンク（前へ/次へ・先頭・末尾・前後 2 ページ。`#site-pager`）と `rel=prev/next` を出す。JS 起動後は `#site-pager` を隠す。範囲外のページは 404。canonical 等は [seo.md](seo.md)。
- 件数: カテゴリ名横の `(N)` は配下を含む件数（`site_count`）、一覧の総数は `/api/sites` の `total`（直下のサイトの COUNT）。

## ピックアップ

トップで、掲載サイトから最大 3 件をランダムに選び、1 件ずつ 8 秒ごとに表示する。画面外・非表示タブ・アニメーション軽減設定（`prefers-reduced-motion: reduce`）では自動切替をしない（軽減設定では最初の 1 件のまま。リロードで別の 3 件）。一時停止/再開の UI は設けない（kako-jun の指示。WCAG 2.2.2 の停止手段は満たさないことを受容、[decisions.md](../decisions.md)）。入れ替え時、フォーカス中のリンクは新しい行の同位置へ戻し、地球儀の国ホバーのホールドは解除する。ファビコンは一覧と同じものを表示する。将来 NEW や確認可能な更新頻度を選出に使う構想があるが、十分な更新履歴や信頼できる日時が揃うまで使わない。人気や閲覧数は使わない。

## NEW タグ

登録日時（`sites.registered_at`）から 30 日未満のサイトに NEW を付ける（期間は仮。未決）。登録日時が不明なサイト、一括投入（`bulk_import=1`）のサイトには付けない。直近登録のグラフ・ACTIVITY（`/api/activity`）も `bulk_import=1` を数えない。一覧の並びは一括投入を後ろにする。新規 INSERT 時は DB のトリガ（migration 0006）が時刻を記録する。

## HUD

画面幅 1200px 以上で表示する（それ未満は非表示）。

- 左上（SITE INDEX）: D1 の実データから、掲載総数と直近 7 日の日別登録数だけを表示する。日別は連続した横バー 1 行固定で、長さは表示範囲の最大日を 100% として正規化する。0 件の日は幅 0、1 件以上は最小幅 3px。凡例は出さない。登録日が不明なサイトは日別に含めない。内部事情（日付不明の件数など）は表示しない。
- 左下（ACTIVITY）: このブラウザで実際に行ったカテゴリ移動（`cd`）・検索（`search`）・地球操作（`look`）を端末風に表示する。新しい行が下に追加され、最大 5 行。画面内のみで、保存・外部送信しない。シェルを実行する機能ではない。

アクセス数や人気順は使わない。

## ファビコン

元サイトで確認したものをローカル配信する（`sites.favicon_path`、`public/icons/`）。未取得・失敗時は何も表示せず、表示時に第三者のサーバーへ問い合わせない。

## アプリとして追加（PWA）

ホーム画面に追加すると standalone（ブラウザの枠なし）で起動する。オフライン時は「オフラインです」だけを表示し、古いカテゴリ・サイトは見せない。タブのファビコンは `<link rel="icon">` で赤地に白の `M` になる（`sites.favicon_path` の各サイトのファビコンとは別物）。ホーム画面アイコンは `public/pwa/` の PNG。仕組みは [architecture.md](architecture.md#pwa)。

## 言語

初期言語は、`localStorage` の `mise-language`（`ja` / `en`）があればそれを最優先し、無ければ `navigator.languages`（なければ `navigator.language`）の先頭が `ja` で始まるときだけ日本語、それ以外は英語（`app.js` の `initialLanguage`）。言語を切り替えると `mise-language` に保存される。サーバー側（SSR・`<html lang>`）は Accept-Language で出し分けず常に英語のまま（同一 URL で言語を変えると SEO 設計（`seo.md` の hreflang・canonical）と CDN キャッシュ（Vary）を壊すため）。判定は `index.html` の `<head>` の同期インラインスクリプトが行い、ja 判定時は `<html lang="ja">` にして `i18n-pending` クラスを付け、翻訳対象（`[data-i18n]`・`#scope-nav`・`#directory`・`#breadcrumbs`）を `visibility:hidden` で初期化まで不可視にする（レイアウトは動かさない）。`app.js` は初回の `applyLanguage()` 後（取得失敗時も）にクラスを外し、保険として 3 秒でも外れる（その時点で `app.js` が未実行なら `<html lang>` は `en` に戻り、`app.js` が遅れて動けば `data-initial-lang` から再び日本語になる）。初期言語の判定は `localStorage` の読み取り失敗（サイトデータのブロック等）と分けて行い、読めなくてもブラウザ言語で判定する。`app.js` の起動直後の静的適用では `<title>` を触らない（SSR の title を保つ）。英語判定ではクラスを付けず挙動は変わらない。サイトの紹介文は `description_en`（英語）と `description_ja` を持ち、英語表示で `description_en` が無いサイトだけ日本語に「(Japanese)」を添える（SSR と `app.js` で同じ扱い）。

## ロゴ

大文字の太い縦長ゴシック体 `MISE`。三毛猫模様のグラデーション。ホバー・フォーカスで模様の境界がなだらかにぼける（`@property --blur` による補間。`prefers-reduced-motion` では即時。`@property` 非対応のブラウザでは補間されず、ホバーで即時にぼける。`@supports` の分岐はない）。M/S の横伸ばしはインラインスクリプトで初回描画前に適用し、通常幅の瞬間を見せない。タイトル下に発音記号 `/ˈmiːseɪ/` を小さく出す。

書体は環境で変わらないよう自己ホストする（`public/fonts/`、`font-display: block` で代替書体を見せない）。ロゴは Anton（SIL OFL、`MISE` の 4 文字だけにサブセット化した woff2）、発音記号は Noto Serif Italic（OFL、`/ˈmiːseɪ/` の文字だけ。Lora は ˈ ː を持たないため不採用）。従来の `Impact` などは font-family の後ろにフォールバックとして残す。ロゴの woff2 は `<link rel=preload>` で先読みし、M/S の実幅測定は `document.fonts.load` の完了後に行う（失敗しても測定して表示する）。woff2 が 2.5 秒以内に届かない低速回線では、そこで見切って現在の書体で先に測って横伸ばしを済ませ（Chromium は block を約 3 秒で打ち切り代替書体を出すため）、到着後にもう一度測り直す。ライセンス全文は `public/licenses/`。woff2 は `uv run --with fonttools --with brotli python3 -m fontTools.subset <ttf> --text=<文字> --flavor=woff2 --layout-features='*' --name-IDs='*'` で作る（Noto Serif は先に `fontTools.varLib.instancer` で `wght=400 wdth=100` に固定）。書体を差し替えるときは woff2 のファイル名のバージョン（`-v1`）を上げる（`_headers` で immutable の長期キャッシュ）。

## アクセシビリティ

- 見出し: ページ先頭に視覚的に隠した `<h1>`（言語に合わせて翻訳）。パンくずは `<nav>`、作者リンクも `<nav>`。`aria-label` は言語切替で `data-i18n-label` により日英が切り替わる。
- 検索バー: 幅 700px 以下ではコンテンツ幅いっぱい（最大 480px）に広げ、701px 以上は従来どおり幅 280px（700→701px の段差は breakpoint として許容）。タッチ端末（`pointer: coarse`）は横向きなど幅に関わらず高さ 44px 以上・文字 16px（iOS Safari が focus でズームしない下限）。キーボード表示時の位置（visualViewport）と実 iOS は未確認。
- 検索結果のライブ領域は `#result-title` だけ（1 文字ごとの再描画で全リストを読み上げさせない）。
- 外部リンク設定ボタン（`#external-toggle`）の状態は、不透明度でなくリング（押下時）とドットで示す。色は白背景で 4.95:1、ダークで約 12:1（実測）。操作ボタンのホバーは不透明度でなく背景の淡い色で示す。
- サイトのリンク右の「別タブで開く」ボタン（`a.site-newtab`、枠・背景なしの ↗ アイコン）は外部リンク設定がオフの間だけ出す（オンなら全リンクが別タブなので `hidden`）。トグル切替で即時に出し入れし、描画時にも現在値で初期化するのでページング・再検索後も一致する。`target=_blank rel="noopener noreferrer"`、`aria-label`/`title` はサイト名入りで「<サイト名> を新しいタブで開く / Open <site> in new tab」（Issue の固定文言にサイト名を前置。スクリーンリーダーで各ボタンを区別するため）。タップ領域は 32px（透明な余白。縦だけ負マージンで行高を増やさず、`position:relative; z-index:1` で後続の説明文より前面に出して実際に押せる範囲を 32px 確保。右は負マージンにせず旗 `.site-place` と重ねない）、hover/focus-visible は色の変化とアウトラインで示す。地球儀の hover は行全体が対象なのでボタン上でも通常のリンクと同じ扱い（タップでは行のタップ移動から除外）。
- サイトの URL は `http:` / `https:` だけをリンクにする（それ以外はテキストのみ）。
- 英語表示で日本語の紹介文を出すときは、その段落に `lang="ja"` を付ける。
