# SEO・クローラ向けの方針

実装は `src/seo.js` と `src/index.js`。

- **配信**: `/`・範囲ページ（`/jp/` `/us/` `/all/` など。トップ・カテゴリ・検索のすべて）と `/sitemap.xml` は Worker が返す。`/robots.txt` は静的ファイル `public/robots.txt`。`/api/` は JS のレンダリングに必要なため robots では塞がない。JS の取得失敗時も SSR 本文があれば消さない。ブラウザで JS が描画した後も title はカテゴリ名を保つ。
- **軽量 SSR**: UI フレームワークや SSR 基盤は使わず、Worker が `HTMLRewriter` で `index.html` に URL に応じた title・description・canonical・OGP と、カテゴリ一覧・パンくず・直下サイトのリンク入り本文（英語）を差し込む。カテゴリ名は `name_en`。ブラウザでは従来どおり JS が同じ領域を描き直す。検索結果・日本語表示・ピックアップは JS 依存。日本語設定のユーザーには、JS 描画までの一瞬 SSR の英語が見える（既知・許容）。
- **範囲（国）の URL**: 範囲は URL の最初の階層に持つ（`/jp/` `/us/` `/all/`。`/<国コード小文字>/` または `all`）。ページの本文は範囲内のサイトだけで作る（カテゴリの件数・直下サイト・範囲切替のリンク）。サイトが 1 件も無い国と不正な値は 404、大文字（`/JP/`）は小文字へ 301。title・description は範囲ごとに違う（全世界は従来の文言、国は国名入り、カテゴリは `Science (Japan) — MISE`）。国名は `public/countries.js` の英語名（ブラウザと Worker の共有表）。範囲切替は `<nav id="scope-nav">` に通常のリンクとして SSR し、範囲どうしが相互にリンクされる。
- **`/` の扱い（200 + canonical）**: ルート `/` は既定範囲（日本）と同じ内容を 200 で返し、canonical と `og:url` と hreflang を `/jp/…` に向ける。301 にしなかった理由: (1) ブランドの顔であるルートを恒久リダイレクトにすると、既定範囲を将来変える・範囲の選び方を変えるときにキャッシュ済みの 301 が残って取り消せない、(2) 既に索引・被リンクにある `/?category=…` は canonical で `/jp/?category=…` に集約できる（ただし従来『全世界』の内容だったものが日本範囲の内容に変わるため、評価の引き継ぎは 301 ほど確実でなく、再評価されるまで揺れる可能性がある。これは範囲を URL に持つ決定の代償として受け入れる）、(3) ブラウザのアドレスバーは `/` のまま（共有しやすい）で、最初のカテゴリ移動・切替から `/jp/` 系に載る。`/` は sitemap に載せない（正規 URL は `/jp/`）。末尾スラッシュなしの `/jp` `/us` `/all` は、存在する範囲のみクエリを維持して `/jp/` へ 301（存在しない値は 404）。この形を Worker に届かせるため `run_worker_first` は `/*` とし、静的ファイルの拡張子（js・css・svg・png など）を `!/*.<拡張子>` で除外している（`/sitemap.xml` は除外しない）。`public/` に新しい種類の静的ファイルを足すときは、その拡張子の除外を足す。
- **カテゴリ URL と canonical**: カテゴリ URL は `/<範囲>/?category=<id>&category=<id>…`（祖先からの順）を 1 範囲・1 カテゴリ 1 ページとして扱う。canonical は範囲と ID に正規化した同形式の URL（`name_ja` 指定や存在しない値は正規化後の URL、解決できなければ範囲トップ）。sitemap には範囲ごとに（`all` と、サイトが 1 件以上ある国だけ）範囲トップと、その範囲内に 1 サイト以上あるカテゴリの正規化 URL を載せ、D1 から動的生成する（サイト 0 件の国は載せない）。`?q=` の検索結果は（空でない場合のみ。`?category=` との併用でも）canonical を範囲トップにし、`noindex,follow` を付ける。
- **言語**: 既定は英語。`<html lang>`・title・description・OGP・JSON-LD・SSR 本文・`index.html` の静的テキストはすべて英語を既定にする。
- **hreflang**: 言語切替は同一 URL 上の JS 切替で URL が分かれず、主要クローラ（en-US）は保存値のない状態（SSR の英語）を見る（初回のブラウザ言語判定はクライアントのみで行い、サーバーは Accept-Language で出し分けない。SSR は常に英語で、主要クローラ（en-US）は SSR の英語を見る。JS を実行する日本語環境では初期化後に日本語になる）。そのため `en` と `x-default` のみ、そのページ自身（範囲ごとの canonical）で宣言し、日本語 URL の分離（`?lang=ja` 等）は行わない（canonical・sitemap・SSR・`app.js` に波及するため、必要になった時に別途設計する）。
- **OGP 画像**: 専用画像は未作成のため `og:image` は未設定（Twitter Card は `summary`）。アイコン確定（Issue #10）後に設定する。
- **JSON-LD**: `WebSite` + `SearchAction`（`/?q={search_term_string}`。`/` は日本範囲として検索結果を返す）。
- **キャッシュと負荷**: `/` は URL ごとに本文が違うため、書き換え後のレスポンスから元アセットの ETag / Last-Modified を除き、`Cache-Control: public, max-age=0, must-revalidate, s-maxage=60`（ブラウザは毎回再検証、共有キャッシュは 60 秒）とする。再帰 CTE のカテゴリ集計は毎リクエスト走るが、現状の件数では軽いと判断している。サイト数・カテゴリ数が増えたら Cache API での URL 単位キャッシュと一覧の件数上限を検討する。
