# SEO・クローラ向けの方針

実装は `src/seo.js` と `src/index.js`。

- **配信**: `/`・範囲ページ（`/jp/` `/us/` `/all/` など。トップ・カテゴリ・検索のすべて）と `/sitemap.xml` は Worker が返す。`/robots.txt` は静的ファイル `public/robots.txt`。`/api/` は JS のレンダリングに必要なため robots では塞がない。JS の取得失敗時も SSR 本文があれば消さない。ブラウザで JS が描画した後も title はカテゴリ名を保つ。
- **軽量 SSR**: UI フレームワークや SSR 基盤は使わず、Worker が `HTMLRewriter` で `index.html` に URL に応じた title・description・canonical・OGP と、カテゴリ一覧・パンくず・直下サイトのリンク入り本文（英語）を差し込む。カテゴリ名は `name_en`。ブラウザでは従来どおり JS が同じ領域を描き直す。検索結果・日本語表示・ピックアップは JS 依存。日本語設定のユーザーには、JS 描画までの一瞬 SSR の英語が見える（既知・許容）。
- **範囲（国）の URL**: 範囲は URL の最初の階層に持つ（`/jp/` `/us/` `/all/`。`/<国コード小文字>/` または `all`）。ページの本文は範囲内のサイトだけで作る（カテゴリの件数・直下サイト・範囲切替のリンク）。サイトが 1 件も無い国と不正な値は 404、大文字（`/JP/`）は小文字へ 301。title・description は範囲ごとに違う（全世界は従来の文言、国は国名入り、カテゴリは `Science (Japan) — MISE`）。国名は `public/countries.js` の英語名（ブラウザと Worker の共有表）。範囲切替は `<nav id="scope-nav">` に通常のリンクとして SSR し、範囲どうしが相互にリンクされる。
- **区画（都道府県・州）の URL（#127）**: 範囲の 2 階層目に区画を持つ（`/jp/13/` `/us/ca/`。`/<国コード小文字>/<区画の英数小文字>/`。区画コードは ISO 3166-2 の `JP-13` を小文字にしてハイフンをスラッシュにした形）。国のページと同じ規則: 本文は区画内のサイトだけで作り、サイトが 1 件も無い区画・不正な形（`/jp/ab-cd/` `/jp-13/` `/jp/13/x/`）は 404、大文字（`/JP/13/`）は小文字へ 301、末尾スラッシュなし（`/jp/13`）は存在する区画のみ `/jp/13/` へ 301（クエリ維持）。title・description は `MISE — Tokyo, Japan: …`・`Cities (Tokyo, Japan) — MISE` のように「区画名, 国名」入り（区画名は `public/regions.js` の英語名、表に無ければコード）。canonical・hreflang・ページ番号・`?q=`/`?tag=` の noindex は国と同じ規則（区画ごとに 1 カテゴリ 1 ページ）。**sitemap** には区画ごとに（サイトが 1 件以上ある区画だけ）区画トップと、その区画内に 1 サイト以上あるカテゴリの URL を国と同じ形で載せる（日本は 47 区画 × 数個〜数十個。官公庁の種別葉が主）。範囲切替の `<nav id="scope-nav">` には国のリンクの下に、サイトのある区画への通常のリンク一覧（`<details class="region-links">`。SSR のみで JS 起動後は消える。JS なしでも・クローラも国ページから区画ページへ辿れる。サイトの無い区画は 404 なので出さない）を出す。国だけ分かって区画が NULL のサイトは国のページにだけ出る。
- **sitemap の URL 数（#127）**: 1 ファイル 50,000 URL・50MB の上限がある。URL 数 ≈ 1（about）＋範囲数 ×（1 ＋ その範囲で件数 > 0 のカテゴリ数）で、範囲 = all ＋ 国 ＋ サイトのある区画。現在は官公庁の名簿の 47 区画 × 数個が主で数千。**区画（最大 384 行の表）× 非空カテゴリ（最大 153）で将来 50,000 を超えうる**ので、`sitemapXml` は総数が `SITEMAP_MAX_URLS`（50,000）を超えたら例外にする（`/sitemap.xml` が 500 になって気づく。黙って切り捨てない）。超える前に sitemap index（範囲ごとのファイルに分割）へ移す。
- **`/` の扱い（200 + canonical）**: ルート `/` は既定範囲（日本）と同じ内容を 200 で返し、canonical と `og:url` と hreflang を `/jp/…` に向ける。301 にしなかった理由: (1) ブランドの顔であるルートを恒久リダイレクトにすると、既定範囲を将来変える・範囲の選び方を変えるときにキャッシュ済みの 301 が残って取り消せない、(2) 既に索引・被リンクにある `/?category=…` は canonical で `/jp/?category=…` に集約できる（ただし従来『全世界』の内容だったものが日本範囲の内容に変わるため、評価の引き継ぎは 301 ほど確実でなく、再評価されるまで揺れる可能性がある。これは範囲を URL に持つ決定の代償として受け入れる）、(3) ブラウザのアドレスバーは `/` のまま（共有しやすい）で、最初のカテゴリ移動・切替から `/jp/` 系に載る。`/` は sitemap に載せない（正規 URL は `/jp/`）。末尾スラッシュなしの `/jp` `/us` `/all` は、存在する範囲のみクエリを維持して `/jp/` へ 301（存在しない値は 404）。この形を Worker に届かせるため `run_worker_first` は `/*` とし、静的ファイルの拡張子（js・css・svg・png など）を `!/*.<拡張子>` で除外している（`/sitemap.xml` は除外しない）。`public/` に新しい種類の静的ファイルを足すときは、その拡張子の除外を足す。
- **カテゴリ URL と canonical**: カテゴリ URL は `/<範囲>/?category=<id>&category=<id>…`（祖先からの順）を 1 範囲・1 カテゴリ 1 ページとして扱う。canonical は範囲と ID に正規化した同形式の URL（`name_ja` 指定や存在しない値は正規化後の URL、解決できなければ範囲トップ）。sitemap には範囲ごとに（`all` と、サイトが 1 件以上ある国だけ）範囲トップと、その範囲内に 1 サイト以上あるカテゴリの正規化 URL を載せ、D1 から動的生成する（サイト 0 件の国は載せない）。`?q=` の検索結果は（空でない場合のみ。`?category=` との併用でも）canonical を範囲トップにし、`noindex,follow` を付ける。
- **試作ビュー `?view=feed`（#52）**: 縦フィードの試作。`noindex,follow` を付け（`src/seo.js` の `wantsNoindex`。検索結果と同じ扱い）、canonical・`og:url`・hreflang は `view` を含まない通常ページ（範囲トップ・カテゴリ）を指す。sitemap には載せない。クローラが辿るリンクも作らない（本文は通常ページと同じ SSR で、フィードは JS が起動後に重ねる）。
- **アバウトページ（`/about/`、#118）**: 静的な `public/about.html` を Worker が `/about/` で返す（`/about` は `/about/` へ 301。`/:scope/` より先に登録する）。DB を使わない説明ページで、SPA の一画面にしなかった理由は、(1) 検索・地球儀・HUD など SPA 本体の読込を要さず軽く開ける、(2) JS なしでも本文が読める（日英を両方 HTML に持ち、`html[lang]` で片方だけ表示。初期言語は本体と同じ保存値（`mise-language`）→ブラウザ言語、クローラは英語）、(3) 履歴が通常の遷移になり、戻るでそのまま `/jp/` に戻れる、の 3 点。CSP は他のページと同じくインラインスクリプトのハッシュ入りを Worker が付ける。**索引に載せる**（`noindex` を付けない。検索結果のような重複・薄いページではなく独立した説明ページのため）。canonical・`og:url`・hreflang（`en` と `x-default`）は自己参照。**sitemap に載せる**（範囲ページより前に 1 行）。title・description は英語（`<html lang>` は JS が日本語環境で切り替え、title も日本語にする）。
- **ページ番号 URL（`?page=N`）**: カテゴリ一覧は 1 ページ 40 件で、2 ページ目以降を `/<範囲>/?category=<id>&page=N` として SSR する（1 ページ目は `page` なしが正規 URL。`page=1` は canonical で `page` なしに寄せる）。各ページの canonical は**自己参照**（2 ページ目以降を 1 ページ目に寄せない）、title に `Page N` を添えて区別する。ページ番号の総数は `total`（葉カテゴリは集計表から正確。`q`・`tag` は検索結果扱いでページ番号なし）から出す。ページ番号リンク（前へ/次へ・先頭・末尾・前後 2 ページ）を本文に出して通常のリンクで全件に辿れるようにし、`<link rel="prev|next">` も出す。範囲外の N と、7 桁以上・数字以外の `page` は 404。検索結果（`?q=`）の SSR にはページ番号リンクも `rel=next` も出さない。sitemap にはページ番号 URL を載せない（カテゴリ URL からのリンクで辿れるため。件数が増えて深さが問題になったら再検討）。**葉でないカテゴリ（子を持つカテゴリ）の件数上限**: `total` は集計表でなく上限付きで数える（`TOTAL_CAP` = 1,000）ので、直下の所属が 1,000 件を超えると SSR のページ番号が 25 ページ（1,000 ÷ 40）で頭打ちになり、後ろのサイトをクロールで辿れなくなる。実害は今は無い（葉でないカテゴリの直下の所属は最大 27 件）。直下の所属が数百件に近づいたら、葉でないカテゴリにも件数を持たせる（集計表の拡張）か、上限を上げる。`?q=` の検索結果は従来どおり `noindex`・ページ番号なし（エンドレススクロールのみ）。`<html lang>`・title・description・OGP・JSON-LD・SSR 本文・`index.html` の静的テキストはすべて英語を既定にする。
- **タグ絞り込み URL（`?tag=`）**: 検索結果（`?q=`）と同じ扱いで、`noindex,follow`・canonical は範囲トップ・ページ番号なし（先頭ページだけ SSR）。タグ別の索引ページ（インデックス対象・ページ番号つき）は未対応で、必要になったら別 Issue。
- **言語**: 既定は英語。`<html lang>`・title・description・OGP・JSON-LD・SSR 本文・`index.html` の静的テキストはすべて英語を既定にする。
- **hreflang**: 言語切替は同一 URL 上の JS 切替で URL が分かれず、主要クローラ（en-US）は保存値のない状態（SSR の英語）を見る（初回のブラウザ言語判定はクライアントのみで行い、サーバーは Accept-Language で出し分けない。SSR は常に英語で、主要クローラ（en-US）は SSR の英語を見る。JS を実行する日本語環境では初期化後に日本語になる）。そのため `en` と `x-default` のみ、そのページ自身（範囲ごとの canonical）で宣言し、日本語 URL の分離（`?lang=ja` 等）は行わない（canonical・sitemap・SSR・`app.js` に波及するため、必要になった時に別途設計する）。
- **OGP 画像**: `public/og/og.png`（1200x630、赤 `#c90018` 地に白い MISE。ロゴと同じ Anton の輪郭。タブ・ホーム画面のアイコンは別意匠（#151））。正本は `public/og/mise-og.svg`（path、フォント非依存）で、`node scripts/build-og-image.mjs` が PNG を書き出す。`index.html` に `og:image`（絶対 URL）・`og:image:width/height/type/alt`・`twitter:image` を静的に持ち、`twitter:card` は `summary_large_image`。全ページ（範囲・カテゴリ・検索）が `index.html` を HTMLRewriter で書き換えるため画像は全ページ共通で、Worker は触らない（言語別の切替もなし）。静的配信は `run_worker_first` の `!/*.png` 除外に乗り、SW のキャッシュ方針は不変。`npm run check` の `scripts/check-og.mjs` が存在・寸法・meta の整合を検査する。意匠は既定案（Issue #98）で差し替え可。ただしサーバー側は `max-age=0` で即反映される一方、SNS 側は URL ごとに長くキャッシュするため、意匠を変えるときはファイル名を変えるか各 SNS のキャッシュを消すこと。
- **JSON-LD**: `WebSite` + `SearchAction`（`/?q={search_term_string}`。`/` は日本範囲として検索結果を返す）。
- **キャッシュと負荷**: `/` は URL ごとに本文が違うため、書き換え後のレスポンスから元アセットの ETag / Last-Modified を除き、`Cache-Control: public, max-age=0, must-revalidate, s-maxage=60`（ブラウザは毎回再検証、共有キャッシュは 60 秒）とする。再帰 CTE のカテゴリ集計は毎リクエスト走るが、現状の件数では軽いと判断している。サイト数・カテゴリ数が増えたら Cache API での URL 単位キャッシュと一覧の件数上限を検討する。
