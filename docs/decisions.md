# 決定記録

kako-jun の方針・合意を、日付と出典 Issue つきで 1 か所に集約する。Issue は作業の記録で、仕様の正本は docs。状態は「実装済」「方針のみ（未実装）」。新しい決定は末尾ではなく該当する節に足す。日付は Issue のコメントに記された日で、2026-11-13 は多くの合意が出た日。

| 2026-11 | 1996 年の Yahoo! JAPAN を参考にしたカテゴリ型ディレクトリ。広告や大手サイトばかりの検索に疲れた人が独立サイトを発見する場 | #1 | 実装済 |

## 申請・状態・比喩

| 日付 | 決定 | 出典 | 状態 |
|---|---|---|---|
| 2026-11-13 | 推薦・取り下げ・訂正は同じ「申請」として 1 つの受付基盤で扱う。依頼であって叶うとは限らない。本人証明はサイト外で行い、mise にトークン確認機構は作らない。公開 API は作らない | #4, #29 | 方針のみ |
| 2026-11-13 | robots.txt の Disallow・noindex など運営者の意思表示は、申請でなく収集時の遵守事項として尊重する | #29 | 収集側は実装済 |
| 2026-11-13 | **比喩は証券取引所で統一**（新規上場 / 上場 / 売買停止 / 監理ポスト / 上場廃止）。「管理ポスト」ではなく「監理ポスト」 | #53 | 方針のみ |
| 2026-11-13 | 審議コーナーは 3 匹の猫（LLM 3 体）の多数決で見せる。MAGI の固有表現は使わない。レッテルを断定しない | #53 | 方針のみ |
| 2026-11-13 | 初期発見の喜びは個人の記録として楽しむ。公開ランキング・リーダーボードは作らない。mise 自身の閲覧数は使わない | #55 | 検証前 |
| 2026-11-13 | 監理ポストは証券取引所で上場廃止の恐れがある銘柄を指定して見守る場所。mise では一時停止（売買停止）の先の、閉鎖の疑い（`long_down` / `suspect`）に当てる | #53 | 方針のみ |
| 2026-11 | リポジトリ自体のライセンスは未決（権利者が決める。docs では決めない） | — | 未決 |
| 2026-11-13 | **グラフは下がらない累積・高値更新の指標だけ**で見せる（下がるのは寂しい）。蓄積のペース（傾き）が速いことが「有名になっていく」感覚。指標は累積のみ（積み上げたページ数、これまでのリンク元ホスト数の累計、到達した最高順位）。「アクセス数」は他サイトのものが取れないので使わない（リンクされ度＝注目度の代理）。現行 HUD の日別登録バー（#34）とは別物 | #55（コメント「決定の記録」） | 方針のみ |
| 2026-11-13 | 「見た」の累計（重複を除く、単調増加のみ）。スクロールで注目しただけで数える。保存しなくても初めて見た日を記録し、あとで注目度が伸びたとき早期発見として見せる。端末内のみに保存。**ストリーク（連続日数）や失う怖さで煽らない** | #58, #55 | 構想・検証前 |
| 2026-11-13 | 累計の表示は**右上に統一**（デスクトップ・スマホ共通）。左上 HUD には置かない。増えたとき数字が一瞬ふくらむだけで、通知・音で煽らない | #58 | 構想・検証前 |
