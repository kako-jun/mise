# mise の構想と技術方針

## 目指す体験

mise は、個人や企業のサイトをカテゴリからたどって発見できるディレクトリ型検索エンジン。運営側から公開サイトを発見・紹介し、利用者が元サイトへ訪問できるようにする。サイトの推薦導線も設ける。サイトごとの一文紹介を、将来エージェントで生成する構想がある。

旧 Yahoo! JAPAN のカテゴリ型画面を参考にしながら、読みやすいゴシック体や現代的な入力欄を用いる。ディレクトリの文字は3D地球の前面に表示し、地球上の場所へ近づける体験を目指す。カテゴリごとに表示を切り替え、パンくずで上位に戻れる。選択中の階層はURLに反映し、直接開いたりブラウザの戻る・進むで移動できるようにする。

サイトの所在地は、運営者の公開情報と推定を区別し、根拠と確認日時を持たせる。IPやサーバーの所在地を運営者の所在地と同一視しない。所在地やサイトレコードの詳細は [サイトスキーマ設計案](site-schema.md) を参照。

## 合意済みの技術構成

- **Cloudflare 内**で配信、API、データベース、定期処理を扱う。
- APIとサーバー側処理は **Cloudflare Workers + Hono**。
- データベースは **Cloudflare D1**。
- 画面は **HTML / CSS / JavaScript**。UIフレームワークは使わない。
- 3D表現には **Three.js** を使う。ソースは `src/client/globe.js`、three 本体は `vendor/three.module.js`（同梱）。`npm run build:globe`（esbuild で minify・tree-shake）が `public/globe.js` を生成するので、globe を変えたら再ビルドして生成物もコミットする（直接編集しない）。`land-110m.geojson` は `scripts/slim-land.mjs` で軽量化済み（小数2桁・property除去）。globe.js はページの load 後に遅延読込し（読込前に押された fly/reset は index.html が記録して起動時に再生する方式。disabled にすると見た目が変わるため。読込失敗時は操作ボタンを隠す）、タブ非表示中は描画を止める。自動回転はドラッグ終了から約4秒の無操作で現在の向きから再開し（速度は0から滑らかに立ち上げ）、ドラッグ中・日本へ飛行中・`prefers-reduced-motion: reduce` では回転しない。
- **Astro は現時点では採用しない**。

## 現在の試作

静的HTML/CSS/JavaScriptとThree.jsによるローカルの叩き台。14の大カテゴリと子カテゴリ、クエリURLによる階層移動、パンくず、手書きサンプルサイトの検索がある。ローカルD1にサンプルを保存し、Workers + Hono のAPIから取得する。検索は取得済みデータをブラウザ内で絞り込み、本格的な検索インデックスではない。3D地球は簡略化した地形であり、正確な地図ではない。推薦リンクは準備中の案内を表示する。

## 今後の実装・未決

- Workers + Hono とD1はローカルで動作する。Cloudflareへのデプロイと定期処理は未実装。
- 実サイトの収集・定期巡回と検索インデックスの構築は未実装。巡回方法や運用の詳細は未確定。
- AIによるサイト紹介文の生成・確認・公開は未実装。利用モデルと生成・承認方法は未確定。既存サンプルは手書き。
- 地球の海岸線データの最終選定は未確定。場所の取得・表示や地球上でのサイト訪問も未実装。
- サイト推薦の受け付けと運営側の確認フローは未実装。

## 推薦の今後の検討

公開Xで作者へメンションする導線、またはサイト内でURLと一言説明を送ってレビュー候補に積む導線を検討する。外部投稿は自動実行しない。受付の安全性、スパム・重複対策、管理レビュー方法は未決であり、現在の画面は準備中の案内のみ。

カテゴリの件数は、そのカテゴリ自身と全子孫の所属サイトを数える。同じサイトが複数の子孫に属していても1件とし、空カテゴリは0件。D1のデータからAPIで集計する。

## 発見の機会

人気や閲覧数を表示・ランキングせず、大手と埋もれたサイトの発見機会を平準化する方針。AI使用の有無もマイナス評価や順位付けの根拠にしない。新規登録を示す NEW タグは必要。試作では登録から30日未満を仮の期間とする（期間は未決）。登録日時が不明な既存サイトはNEWにしない。新規INSERT時はDBが時刻を記録する。収集済み2件については、旧ローカルマイグレーションの適用履歴に記録された時刻を用いる。

トップのピックアップは現状、サンプルからランダムに最大3サイトを選び、1件ずつ8秒ごとに表示する。画面外・非表示タブ・フォーカス中・ポインター上・アニメーション軽減設定では自動切替を停止する。将来NEWや確認可能な更新頻度も選出に使う構想だが、十分な更新履歴や信頼できる日時が揃うまで使用しない。人気や閲覧数は使わない。

ファビコンは元サイトで確認したものをローカル配信する。`public/icons/llll-ll.png` の取得元は llll-ll の [favicon](https://llll-ll.com/favicon.ico)（トップページで指定、2026-11-12確認）。未取得・失敗時は何も表示せず、表示時に第三者のサーバーへ問い合わせない。

mise を訪れず内容を閲覧するための公開RSSや外部向け公開APIは設けない方針。現在の `/api` はブラウザ用であり、そのネットワーク上のエンドポイントは利用者が直接呼び出せる。外部アクセスの完全防止は保証せず、正式な配信・アクセス方法は別途設計する。

## マスコット

mise のマスコットは、MISE と MIKE の語感を掛けた三毛猫が基本。猫耳などの猫モチーフをデザインに活用する。具体的なキャラクターの姿、画像、実装方法は未決。

サイト一覧にトップページのスクリーンショットをサムネイルとして表示する構想がある。取得日時や失敗状態、更新・削除、未決事項は [サイトスキーマ設計案](site-schema.md#サイトのスクリーンショット将来構想) を参照。現在は撮影・公開していない。

上部HUDはD1の実データからサイト総数と直近7日間の登録日が分かる件数を表示する。登録日が不明な件数は別に示し、日別棒グラフには含めない。個別サイトの最終確認日時とタグを表示できる。試験収集の2件には取得記録に基づく確認日時と分類を登録し、それ以外の不明値は不明のまま。巡回履歴の時系列は記録していない。アクセス数や人気順は使わない。

ピックアップでも一覧と同じ確認済みファビコンを表示する。将来サムネイルを取得できた場合にも表示を検討し、未取得時は表示しない。詳細は[スクリーンショットの構想](site-schema.md#サイトのスクリーンショット将来構想)を参照。

## SEO・クローラ向けの方針

- **キャッシュと負荷**: `/` は URL ごとに本文が違うため、書き換え後のレスポンスから元アセットの ETag / Last-Modified を除き、`Cache-Control: public, max-age=0, must-revalidate, s-maxage=60`（ブラウザは毎回再検証、共有キャッシュは60秒）とする。再帰CTEのカテゴリ集計は毎リクエスト走るが、現状の件数では軽く、s-maxage で足りると判断。サイト数・カテゴリ数が増えたら Cache API での URL 単位キャッシュと一覧の件数上限を検討する。
- **配信**: `/`（トップ・カテゴリ・検索のすべて）と `/sitemap.xml` は Worker が返す（`wrangler.jsonc` の `assets.run_worker_first` に `/api/*`・`/`・`/sitemap.xml` を指定）。`/robots.txt` は静的ファイル `public/robots.txt`。`/api/` は JS のレンダリングに必要なため robots では塞がない。JS の取得失敗時も、SSR 本文があれば消さない。ブラウザで JS が描画した後も title はカテゴリ名を保つ。
- **カテゴリURLとcanonical**: カテゴリURLは `/?category=<id>&category=<id>…`（祖先からの順）。これを1カテゴリ1ページとして扱い、canonical は ID に正規化した同形式のURL（`name_ja` 指定や存在しない値は正規化後のURL、解決できなければ `/`）。sitemap には本文のあるカテゴリ（配下に1サイト以上）の正規化URLと `/` を載せ、DB から動的生成する。`?q=` の検索結果は （空でない場合のみ。`?category=` との併用でも）canonical を `/` にし、`noindex,follow` を付ける。
- **既定言語**: 既定は英語。`localStorage` の `mise-language` が `ja` のときだけ日本語（ブラウザ言語での自動判定はしない）。`<html lang>`・title・description・OGP・JSON-LD・SSR本文・`index.html` の静的テキストはすべて英語を既定にする。
- **SSR可否**: UIフレームワークや SSR 基盤は使わず、Worker が `HTMLRewriter` で `index.html` に URL に応じた title・description・canonical・OGP と、カテゴリ一覧・パンくず・直下サイトのリンク入り本文（英語）を差し込む「軽量SSR」にした。カテゴリ名は `name_en`。サイトは名前が言語共通で、紹介文は `description_en`（英語）と `description_ja` を持ち、英語表示では `description_en` を使う。`description_en` が無いサイトだけ `description_ja` に「(Japanese)」を添える（SSR と app.js で同じ扱い）。ブラウザでは従来どおり JS が同じ領域を描き直す。検索結果・日本語表示・ピックアップは JS 依存のまま。日本語設定のユーザーには、JS 描画までの一瞬 SSR の英語が見える（既知・許容）。
- **hreflang**: 言語切替は同一URL上のJS切替でURLが分かれず、クローラは保存値のない状態（英語）しか見ない。そのため `en` と `x-default` のみ同一URLで宣言し、`?lang=ja` のような日本語URLの分離は行わない（canonical・sitemap・SSR・app.js の全部に波及するため、必要になった時に別途設計する）。sitemap と canonical は言語非依存の同一URL。
- **OGP画像**: 専用画像は未作成のため `og:image` は未設定（Twitter Card は `summary`）。#10 のアイコン確定後に設定する。
- **JSON-LD**: `WebSite` + `SearchAction`（`/?q={search_term_string}`。`app.js` は `q` 付きURLで検索結果を表示する）。
