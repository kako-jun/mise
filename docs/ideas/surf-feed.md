# サーフモード・縦フィード

Issue #52。新着・カテゴリ別の縦ビューの入口と表示は [UI の仕様](../design/ui.md#新着と縦ビュー) を参照。

## 狙い

縦スクロールの SNS やショート動画のように「ダラダラ見てしまう」魅力を、従来の Web ページ巡回（ネットサーフィン）で出す。ネットサーフィンの復興が mise の核という位置づけ。

## 考え方

- 「次へ」の気持ちよさが核。1 つ見終わったら次が自然に出る。選ぶコストを下げる。
- **サーフモード**: 範囲（国）・カテゴリを指定し、ほぼランダム（新着・更新を少し優遇）に次のサイトへ進む。キー（j/k, ↓）・スワイプ・ボタンで次へ・前へ。戻って来られる。
- **縦フィード**: サイトを 1 枚のカード（プレビュー画像・サイト名・リンク先のホスト名〔小さく 1 行。[design/ui.md](../design/ui.md#ファビコン)〕・一言・国旗/区画・タグ）として縦に流す。カードごとにスナップ。「開く」ボタン。
- **リンクをたどる**: そのサイトが外部リンクしている掲載サイトを提示する（ウェブリング的）。発見パイプラインが持つ外部リンクを使う。
- **開き方**: 埋め込み可のサイトは画面内のパネル、不可は新しいタブ。いきなりブラウザは作らない（[browser-and-thumbnails.md](browser-and-thumbnails.md)）。
- **守るもの**: 依存を煽る暗いパターン（通知・連続報酬の演出・終わりが見えない設計）を目的にしない。終わりを見せる（あと何件）選択肢も持つ。

## 画面の方針

新着を縦ビューの主な入口にする。各カテゴリの箇条書きでも、そのフォルダの縦ビューに切り替えられる。縦ビューの上部には帯を置かず、背景の上に、箇条書きへ戻る矢印・左右中央の検索欄（スマホは矢印とカウンターのあいだの 1 行）・右上の猫サーフィンと見たサイト数を重ねる（#198）。

## 長い紹介文

サイト名と一言紹介に加え、「どんなサイトで、どんな作者で、何が一芸か」まで書いた 200〜400 字程度の紹介文を、ショート動画のコメントのようにサムネイルに重ねて読める。`long_description_ja` / `long_description_en` を LLM 工程（[llm-judging.md](llm-judging.md)）で生成する案。事実だけ（サイト自身の記載に根拠があるもの）で、根拠の引用を持ち、推測・誇張・評価の捏造をしない。根拠が薄ければ短く済ませるか null。成人向け属性があるものは中立・婉曲に。About 系ページの追加取得（同一ホスト、robots 遵守、1 サイト最大 2 ページ）が前提。

## カード

カードの上部にサムネイル、背景に同じ絵をぼかして表示し、下部の文字に薄い影を重ねる。サムネ未取得は ID から決まる三毛猫模様と頭文字。最後には終了カードを表示する。

## 見たサイトの累計（Issue #58）

「見た」はカードが画面の 60% 以上見えて現在のカードに切り替わった瞬間（#277。滞在待ちなし。連続送り・通過しただけのカードは数えない（指・ホイールは止まって揃った瞬間）。自動送り #199 で進んだカードも数える。放置で全件見たことになりうるが、仕様として許容）。累計は重複を除き、端末内にだけ保存する。最後のカードから件数と内訳（月ごと・国別・カテゴリ別）を確認でき、JSON の書き出し・読み込みにも対応する。

## 自動送り（Issue #199）

一定時間たつと自動で次のサイトへ進む。1 枚 **12 秒**（`feed.js` の `AUTO_ADVANCE_MS`）。進行は画面下端に貼り付く高さ 4px のバー（スマホは全幅、PC はカード列幅 520px）（`.f-progress`。`transform: scaleX` だけを毎フレーム更新。カードが変わるとリセット）で見せる。

- **常に有効(動きを減らす設定を除く)**: 「自動」ボタンとオン/オフの切り替えはない（#292）。ただし `prefers-reduced-motion: reduce` のときは自動送りしない（旧版も既定オフだった）。バーも出さず押せない。設定の切り替え（`change`）は即時に反映する。旧版が保存した localStorage の `mise-feed-auto-v1`（'on' / 'off'）は読まず、残っていても動作に影響しない（'off' でも自動送りは動く）。
- **読んでいる人が止める手段（WCAG 2.2.2）**: 進行バー（`.f-progress`）が一時停止・再開の操作を兼ねる（`role="button"`・`tabindex="0"`・`aria-label`「自動送りを一時停止」・`aria-pressed`）。タップ/クリックか、フォーカスして Enter / Space。見た目は 4px のまま。バー自体はポインタを受けない（`pointer-events: none`。固定レイヤーで `.f-scroll` の兄弟なので、受けると下端から始めたスワイプを飲み込んだ）。代わりに `.f-scroll` で、タッチは短い `touchend`（ブラウザが指の近くのリンクへ click を寄せるので click を止めて奪う）、マウスは `click`（スワイプ・ドラッグでは出ない）を、バーの幅の範囲・下端 24px（`AUTO_TAP_PX`）で、リンク/ボタン以外の上のタップを一時停止/再開として拾う。キーボード・読み上げ用の `role=button` 要素はバーのまま（フォーカスで輪郭が出る。reduce・終了カード・最初のフレームまでは `inert`）。停止中はその位置で静止し、色を灰色に落として分かるようにする（点滅なし）。再開は同じ操作で、止めた位置から続ける。別のカードへ移ったら（スクロール・キー・ボタンのどれでも）一時停止は解け、そのカードで 0 から伸びる。既知の制限: 下端 24px で始めたスワイプ・ホイールはバーが受けるのでスクロールしない（カードの上で操作する）。
- **バーの開始 = カードが切り替わって止まった瞬間**（#292）: 指・ホイール・キー・上下ボタン・自動のどの経路でも、カードが境界に揃って止まった瞬間（`scrollend`。無い環境は最後の `scroll` から 150ms。#277 のスコア更新と同じ契機）に、待ち時間なしで 0 から伸び始める。指が触れている間（カード本文でも）、スクロール・寄せのアニメーション中（`feed.js` の `autoMoving`）は、バーは 0 に戻って薄く待ち、進めない（動いている最中に誤って送らないため）。
- **止まる条件**: 「もっと見る」展開中、詳細パネルが開いている間、検索欄にフォーカス中、タブ非表示、表示中カード内のフォーカス（リンク/ボタン等どこでも。`:focus-visible` の条件なし。j/k で送った直後のカード自身は除く）、リンク/ボタンの hover。止まっている間はバーを薄くする。
- **再開（実ブラウザで確認、`scripts/e2e-feed-autopause.mjs`）**: 上の止まる条件が解けてから 4 秒（`AUTO_RESUME_MS`）待って 12 秒を最初から数え直す（閉じた直後・離れた直後に勝手に動かさない。検索を閉じて 4.0 秒後にバーが伸びる）。この 4 秒待ちの用途はここだけ。カードの切り替わり直後・一時停止の解除・**タブ復帰**（`visibilitychange` で `restart`。非表示中は rAF が止まるので、1 秒超の隙間でも同じ）は待たず 0 から（一時停止の解除は位置から）。画面の向きの変更は何もしない（進行は続く）。
- **以前の遅れの原因（#292）**: 旧版は wheel / touch / pointerdown / keydown のたびに `poke` で「4 秒の無操作待ち」を入れていた。指・ホイール・キー・ボタンで切り替えると、その入力（touchend 等）で 4 秒待ちが入り、カードが止まってからさらに約 3.5〜3.9 秒バーが始まらなかった（実測）。自動送りは入力を伴わないので `poke` を通らず、カード切り替え（IntersectionObserver）の `reset` だけで即伸びていた。操作の直後に待つ仕組みを廃止し、「動いている間は 0 で待つ・止まったら始める」に一本化した。
- **末尾**: 終了カードでは止まり、巻き戻さない。バーも隠す（押せない）。
- **タブ復帰**: ブラウザは非表示中 rAF を止めるので、`tick` は前フレームから 1 秒超の隙間を「保留」とみなし、
- **移動**: 既存の `step(+1)` を使う（scroll-snap・#196 の地球休止・「見た」判定・上下ボタンの現在位置と同じ経路）。時間の進みは `feed-lib.js` の `makeAutoAdvance`（純関数。`tests/feed-view.test.mjs` で検証）。

## データ取得と表示

読み込みは `public/index.html` のフックが `?view=feed` のときだけ縦ビュー用 CSS と JavaScript を足す。読み込み失敗、または 10 秒たっても `#feed` が現れないときは通常表示に戻る。

- **データ**: `/api/categories` で階層を解決し、`/api/sites` へ範囲と末端フォルダの ID を渡す。新着は `category=recent`。一度に最大 100 件、合計 500 件まで取得する。ページ番号付きのフォルダは最初に箇条書きと同じ 40 件を取得し、次からカーソルでたどる。続きがある場合や一部の取得に失敗した場合、最後のカードから箇条書きへ移動できる。フォルダの箇条書きでは、表示済み件数の次の行を `#site-row-N` で示す。以前の `?cat=`・`?scope=`・`?sort=` リンクも開ける。
- **描画(帯と窓、#278)**: 取得した全件の空の枠（高さ 100dvh・`scroll-snap-align: start`・`scroll-snap-stop: always`）を縦 1 本に並べ、中身（サムネ・名前・説明・タグ・場所・足元）は**現在のカードの前 2 枚〜後 3 枚だけ**描く（`feed.js` の `WIN_*`、`feed-lib.js` の `windowRange`）。現在のカードだけ同期、前後の先読みは近い順に 1 フレームに 1 枚（一度に複数枚をまとめて描かない）。中身を捨てた枠は `inert`（支援技術に空の要素を読ませない）。サムネは `img.decode()` が済んでから見せ、先読み済みの隣は最初から不透明（少しドラッグした時点で隣の名前・説明・サムネが見える）。窓から 3 枚以上離れた中身は捨てて枠だけに戻す（描画済みは最大およそ 12 枚、DOM ノードは 500 件でも約 1,800）。枠の高さは固定なので捨てても位置は動かない。読み込み中は「読み込み中…」を出す。
- **離したあとの寄せ(#278)**: 実測（Chromium・390×844・CDP のタッチ）でブラウザ標準の snap は、ゆっくり離すと約 130〜190ms で寄るが、勢いのある離し方では 0.7〜0.8 秒かけて慣性で流れてから止まり「ぐいっと」寄らなかった。指を離した瞬間の位置と速度で行き先（触り始めから ±1 枚。半分超で次・速い flick は 1 枚・2 枚は飛ばさない。`settleTarget`）を決め、150〜300ms の ease-out（`settleMs`）で寄せる。触っている間と寄せている間だけ CSS の snap を外し（`scrollSnapType='none'`）、終わったら戻す（同時にかけない）。キー・ボタン・自動送り・ホイールは従来の snap。
- **長文**: `long_description_*` が無いカードは長文欄を出さない。ダミー文は開発用の `?mock=1` のときだけ。
- **通常 UI のデータ取得**: 読み込み失敗時に通常画面を表示できるよう、縦ビューでも `app.js` の初期化が裏で動く。
- **安全**: 「開く」リンクは http(s) の URL だけ（`javascript:` などは出さない）。サムネは同一オリジンの絶対パスのみ（`//host`・`/\host` は不可）。「見た」JSON の読み込みは 1MB まで、キーは ID の形のみ。
- **CSP**: `script-src 'self'` ＋インラインスクリプトのハッシュ、`style-src 'self'`、`img-src 'self' data:`、`connect-src 'self'` のまま違反なく動く。第三者へはアクセスしない（サムネは同一オリジンの絶対パスのみ。無ければ三毛猫の代替絵）。`tests/feed-view.test.mjs` が静的に守る
- **SEO**: `?view=feed` は `<meta name="robots" content="noindex,follow">` を出し（`src/seo.js`）、canonical は通常ページを指す。sitemap には入れない。
- **端末内保存**: 見たサイト累計・言語・テーマ・新しいタブ設定は localStorage を try/catch で包み、使えなくても動く。
