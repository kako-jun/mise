## 実装済みの取得元(2026-11-21)

種類は取得元で決まるだけで、判定前に種類を推定せず LLM にも渡さない。種類の記録先は下記。

- **(4)(5) Wikidata**: `data/wikidata-leaf-map.csv` に 5 行(`note` の先頭に `[種類4 …]`/`[種類5 …]`)。見込み件数は日本関連 + P856 ありの SPARQL COUNT(2026-11-20): ウェブサイト `Q35127` 276・インターネット上のサービス `Q1668024`(子クラス込み)257・ソフトウェア `Q7397` 40・上場企業 `Q891723` 581・企業 `Q6881511` 1,223。行ごとの `max_rows` は 100〜300 で、夜をまたいで続きから取る既存の仕組みのまま。`Q4830453`(business)は直接の件数が約 24,000 と大きく企業の偏りを強めるため入れない。国の条件が日本固定のため、**日本に関係しない海外サービスのトップ(Instagram 等)はこの経路では取れない**(未対応。別の取得元が要る)。
- **(1)(2)(3) discover-links の起点**: `data/discover-seeds.csv`(列 `url,kind,area,note`、`kind` は `town-shop`/`personal-text`/`doujin`)。町の店 14(商工会・商工会議所・観光協会の会員一覧、商店街リンク集)・個人テキスト 7(個人リンク集、個人サイト紹介記事)・同人 5(イベントの一覧、同人音楽・ゲーム制作のリンク集)。実在と外部リンクの有無を 1 回ずつ取得して確認したものだけ。`discover-links` は起点のパス付き URL をそのまま取得する(従来の既掲載サイトのトップはパス `/`)。台帳の `source='links'`・`source_detail`=起点ページの URL で、起点 → 種類は CSV を引く。
- **2026-11-21 追加**: 八女・吹田・久留米東部の会員ホームページ一覧、個人リンク集2ページ、同人音楽・ゲーム制作のリンク集3ページ。いずれも既存の取得経路で robots を確認して HTTP 200 と外部リンクを確認した。外部リンクには目的外のサイトも含むため、候補の掲載可否は後段で判定する。共有ホスト配下のリンク先は現状ホストの `/` に丸められるため、`/~user/` の個人サイトを別々に発見するには別途対応が必要。
- **残りの探索**: 目標の目安は町の店 15〜30、個人テキスト・同人は各 10〜20。コミケ・コミティア・文学フリマ等の公式はカタログが別サービスでサークルサイトへのリンクが少ない。商店街自身の「加盟店一覧」は店の自前サイトへ出ないことが多く(巣鴨・錦市場・アメ横等は自サイト内のページ)、goope.jp 上の商工会は店が共有サービス配下になるため起点に入れていない。

## 案(残り)

1. **追加枠(`--max-add`)の種類別配分**: 夜間の枠を 5 種類(町の店 / 個人テキスト / 同人 / 主要サービスのトップ / 主要企業)に配分する。種類は発見元(`source`)で決める(下の取得元の表)。判定前に種類を推定しない(LLM の `hint_leaf` を渡さない既存の原則と同じ)。
2. **取得元を増やす**:

| 種類 | 取得元の案 | 備考 |
|---|---|---|
| 町の店 | 商店街・商工会・観光協会の加盟店ページ → 店の自前サイトへのリンク(`discover-links` の起点に足す) | 食べログ等へのリンクは `platform_page` で落ちる。自前サイトだけ残る |
| 昔ながらの個人テキスト | 個人サイトのリンク集・Webring・古い ISP の個人ページ(`ne.jp`・`asahi-net.or.jp` 配下)を `discover-links` の起点に | 更新停止の個人は #129 で原則登録しないので、更新の兆候があるものを優先 |
| 同人サークル | 同人イベント・ジャンルのサークル一覧ページ、サークルのリンク集 → サークル自前サイト | 成人向けは `adult` 属性で記録(拒否に使わない) |
| 主要な Web サービスのトップ | Wikidata の「ウェブサイト/ソフトウェア/オンラインサービス」の項目(`P856`、対応表 `data/wikidata-leaf-map.csv` に行を足す。葉は既存の IT・サービス系) | Wikidata は CC0。`platform_page` により `instagram.com/<店>` 型の P856 は落ちる |
| 主要な企業の公式サイト | Wikidata の企業(`Q4830453` 等。国=日本)を対応表に足す | 既存の発見元が企業に偏っている面があるので、枠の上限を決めて足す |
| (参考)上位ドメイン一覧(Tranco 等) | 未決。**「#9 の判断」は Migemo の Issue で該当する判断が見つからなかった**ので、使う前に kako-jun に聞く | 利用条件・再配布の可否を確認してから |

3. **測定してから決める**: 実装の前に、収集機の台帳で `site_kind` 別・`source` 別の内訳と、各取得元の見込み件数(Wikidata は SPARQL の `COUNT` を 1 回)を出し、枠の配分比を kako-jun と決める。
