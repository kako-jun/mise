# エンドレススクロール・検索の拡張・PWA（構想）

**エンドレススクロールは実装済み（#51。現行仕様は [ui.md](../design/ui.md#一覧のページングエンドレススクロール)・[seo.md](../design/seo.md)）。それ以外（検索の拡張・PWA）は構想で、実装済みではない**。

## エンドレススクロール（Issue #51、合意 2026-11-13。実装済み）

ページングは単なる一覧技術でなく、発見体験の土台（[surf-feed.md](surf-feed.md)）。

- `/api/sites` を全件返しから、並びのキー（更新日・id）によるカーソル方式（limit + cursor）に変える。カテゴリ別・範囲別の件数は別に返す。官公庁台帳が入っても軽いこと。
- 末尾の番兵（IntersectionObserver）で続きを読む。読み込み中・失敗時（再試行ボタン）・末尾（あと何件）を常に表示する。
- クロール用に各ページへ通常の URL（`?page=N` 等）を持ち、SSR の HTML にリンクと `rel=next/prev`・canonical を出す。JS なしでも順に辿れる。
- 戻る操作で読み込み済み件数とスクロール位置を `history.state` から復元する。

## 検索の拡張（Issue #31・#9）

- 現状の検索はサーバー側の部分一致（`sites.search_text`。NFKC + 小文字化）で、タグ名には一致しない。タグは結果のタグを押して AND で絞り込める（実装済み・決定 2026-11-14: [ui.md](../design/ui.md#タグで絞り込む31)）。
- 構想: 既定は新しい順のまま、切替で「マッチ度」順。検索をサイト名・説明に加えタグ、意味的な曖昧検索まで広げる。各サイトのベクトル表現を管理する案。賢い検索アルゴリズムが mise の一芸になりうるかを検証する。
- 調査項目: タグ体系、埋め込み方式（D1 に保存して Worker 内でコサイン類似度 / Cloudflare Vectorize / 手元で一括生成）、日本語での品質評価、費用、検索語の埋め込みを公開サーバーから毎回呼ぶ場合の費用上限（従量課金 API を自動で呼ぶ方針は避けている）。比較表を作り、方式は kako-jun と合意してから実装する。
- Migemo によるローマ字検索（#9）は検討のみ。
