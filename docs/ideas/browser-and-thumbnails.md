# 画面内でサイトを開く・サムネイル・3D の町（構想）

Issue #41・#6。**いずれも実装済みではない**。実測と撮影の試験があるだけ。

## 方針（決定）

- **いきなりブラウザは作らない**（kako-jun 2026-11-13、Issue #41）。アプリ版（Tauri 等）は将来の候補で、今は作らない。まず Web 版の画面内パネル（埋め込み可のサイトのみ）を、必要になれば試作する。iframe を拒否する（X-Frame-Options / CSP `frame-ancestors`）のはサイト側の意思表示なので**迂回しない**。サーバーで中身を取って書き換え表示するプロキシ方式や、JS で取得して差し込む方式は採らない。
- mise は https なので、http のみのサイトは混在コンテンツで埋め込めない。
- アプリ版（Tauri 等の WebView）なら埋め込み拒否は無関係で、本物のブラウザ体験を作れる。PWA（#10）の後に別プロジェクトとして検討する。

## 段階

1. 埋め込み可否の判定（決定論）— 実測のみ済み（[procedures.md](../collection/procedures.md#埋め込み可否の判定)、結果は [trials.md](../collection/trials.md#埋め込み可否の実測2026-11-13issue-41)）。巡回時に `embeddable` を記録する実装は未着手。
2. 画面内パネル: 埋め込み可のサイトは sandbox 付き iframe（top 遷移・ポップアップ禁止、allow 最小）、不可のサイトはプレビュー画像＋「開く」。戻る/閉じるは mise 内で一貫。モックアップ先行で触って決める。未着手。
3. スクリーンショット取得（巡回時、サイト別・低頻度・robots 遵守）。**撮影の試験用スクリプトは実装済み**（PR #56、設計・作法・試験結果は [thumbnails.md](../collection/thumbnails.md)）。R2 への保存、D1 の列、カード（フィード）への統合は構想。
4. 地球儀上の 3D 表示: 県・州座標に小パネル（スクリーンショットのテクスチャ）を立てる。密集地はズームで展開/遠景でクラスタ。生 iframe の 3D（CSS3DRenderer）は負荷が高いので後回し。
5. アプリ版（Tauri）。別 Issue。

## サムネイル

設計案: サイトのトップを PC 画面（1280x800）の最初の画面で撮影し、**低解像度の横長 1 枚**（幅 320px 前後、WebP）にする。幅 16px のプレースホルダ（data URI）を添える。巡回と同じ作法（robots・UA・間隔・1 サイト 1 回）。画像は R2 に置き、D1 には URL・撮影日時・状態だけを持つ案（Cloudflare R2 と Browser Rendering は候補で、採用は確定していない）。`noarchive` / `noimageindex` のサイトは撮影しない。成人向け属性のサイトは出さない（ぼかし/無地）。取り下げ申請が通ったら画像も消す。画像の保存先と失敗詳細、保持期間、古い画像の再取得・置換・削除条件、許諾や公開・削除方針は未決。成功した画像と直近の失敗は両立するため、最後の成功日時と最後の試行日時・結果は別に持つ。

撮影の試験（Issue #41 のコメントと [thumbnails.md](../collection/thumbnails.md)、2026-11-13）では、スマホ画面を別に持つと容量が約 2.7 倍になるため、PC 版の 1 枚だけを推奨とした。試験の数字と設計は thumbnails.md を参照。画像は `var/thumbs/`（コミットしない）にのみ出力され、公開はしていない。
