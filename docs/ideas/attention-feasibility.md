# 注目度の積み上げグラフの実現性検証（#55）

2026-11-13 時点の観測。件数・順位はすべて「検証時点の観測」で、再測定すれば変わる。ステータス: 検証のみ（アプリ本体は未変更）。方針は #55 の決定の記録に従い、**下がらない指標（累計・高値更新）だけ**で評価する。「アクセス数」は他サイトのものを取れないので使わず、データの意味（積み上げたページ数、リンクされ度の最高点）をそのまま書く。

## 結論（先に）

| 指標（意味） | 可否 | 通信量・時間 | 一言 |
|---|---|---|---|
| A. 積み上げたページ数（Wayback の初回保存日の累計） | 小さな個人サイトなら可。大きなサイトは不安定（13 サイト中 成功 10・失敗 3） | 1サイト 数十KB・10〜90秒 | 作者の積み上げの形が見える。ただし保存の集中で段差が出る |
| B. これまでのリンク元の累計（Common Crawl の edges の和集合） | 1 回きりのオフラインバッチなら可能。定常運用には重い（実行せず見積もり） | 1 公開分で 3.7〜21GiB（4 節の表） | 推移には複数公開分が要る。アプリや日次ジョブからは不可 |
| C. 到達した最高順位（ranks の running max） | 可。追加の取得なしで作れる | 1公開分あたり先頭 200MB・約 10 秒 | 単調だが、順位が公開ごとに大きく揺れるので一回の外れ値で固定される |

株価のような「上がっていく線」は **A（努力の累計）が最も自然**。C は階段状の「最高値更新」の演出に向く。B は通信量・処理が一段重く、後回しが妥当。

## 1. Common Crawl のウェブグラフ（確認した事実）

- 一覧: 公式の Web Graphs ページ（`graphinfo.json` も公式に提供）。2017 年の公開から 55 リリース。四半期ごとに 3 か月分のクロールをまとめて公開（最新は 2026-aug-sep-oct、2026-11 時点）。
- ホスト単位とドメイン単位（支払いレベルドメイン）の両方がある。公開は `https://data.commoncrawl.org/projects/hyperlinkgraph/<リリース>/{host,domain}/`。
- 順位ファイル `<リリース>-{host,domain}-ranks.txt.gz`。列: `harmonicc_pos, harmonicc_val, pr_pos, pr_val, host_rev, n_hosts`（タブ区切り、ホスト名は逆順表記。ドメイン版のみ n_hosts あり）。**並びは名前順でなく調和中心性の順位順**。名前での二分探索 Range は使えない。
- 順位ファイルのサイズ（HEAD、2020 年以降の公開）: ドメイン版は各 約1.9〜2.7GiB、ホスト版は各 約4.4〜11GiB（2018 年以前は最大 38GiB）。2017 年の 3 リリースは順位ファイルなし。
- 入次数（リンク元数）の列は順位ファイルにはない。edges と転置グラフ `-t.graph` のみ（サイズは 4 節の表）。転置グラフを Range で引くのに必要な `.offsets` は公開されておらず（404）、1ノードだけ取り出すこともできない。
- 利用条件: Common Crawl の Terms of Use に従う（データは自由に利用可、サイト側コンテンツの権利は元の権利者）。ライセンス条文は実装段階で原文を再確認する。

### 取得の方法と通信量
順位は順位順なので、**先頭 200MB（Range）を読むだけで上位約 750 万ドメイン**まで取れる（全体約 1 億ドメイン）。掲載サイトの約 3 分の 2 はこの範囲に入ったが、範囲外のサイトは「データなし」になる。10 リリース × 200MB ＝ **約 2.0GB（上限 3GB 以内）**、1 リリース 8〜15 秒。UA を明示し、リクエスト間に 2 秒空けた（再現スクリプトの UA は `MiseResearchBot/0.1 (+https://github.com/kako-jun/mise)`）。

## 2. 掲載済み 37 サイト・比較サイトの観測（C: 到達した最高順位）

37 サイトの親ドメインを、10 リリース（2020-10〜2026-11）の先頭 750 万位以内で引いた結果:

- 最新リリースで順位が出た: 25 / 37。出なかった（先頭 750 万位より下、または収録なし）: 12 / 37。うち 4 件は作者自身の `llll-ll.com` 配下（サブドメインは親ドメインとして集約）。
- 最新リリースでの順位帯: 1 万位以内 2、10 万位以内 8、100 万位以内 15、データなし 12。
- 共用ホスティング（`ne.jp`、`cweb.tk`、`asahi-net.or.jp` 配下の個人サイト）は、親ドメインの値になってしまい、そのサイト自体の値ではない。パス付き URL のサイトは単位が合わない。
- 比較サイトの観測（調和中心性の順位。2020-10 公開 → 2026-11 公開、括弧内は 10 公開分での最高）:

| サイト | 2020-10 | 2026-11 | 最高 | 読み取れること |
|---|---|---|---|---|
| gwern.net | 308,541 | 9,818 | 9,818 | **上昇が見える**（30 万位 → 1.5 万位 → 1 万位。揺れは小さめ） |
| ciechanow.ski | 6,696,718 | 370,784 | 37,191 | 上昇が見えるが、公開ごとの揺れが大きい（2026-05 は 3.7 万位、次で 37 万位に戻る） |
| maggieappleton.com | 1,482,111 | 369,670 | 49,003 | 同上。100 万位台から上がるが不安定 |
| nullprogram.com | 342,784 | 372,820 | 39,954 | 上がったり戻ったりで、推移は読めない |
| paulgraham.com | 3,675 | 3,256 | 2,374 | 検証期間の始点で既に上位。横ばい |
| kottke.org / waitbutwhy.com / danluu.com | 約 5,000〜9,000 | 355,509 / 2,636 / 8,055 | 5,280 / 1,276 / 3,645 | 始点で既に上位。ときどき 30 万位台に落ちる外れ値（crawl の範囲の違い） |

  つまり、**「有名になっていく過程」が見えたのは gwern.net（明瞭）、ciechanow.ski・maggieappleton.com（不安定ながら）**。見えなかった差は、(1) 検証期間の始点（2020-10）で既に上位だったサイト（paulgraham.com ほか）は、それ以前に上がった分が範囲外、(2) 取得範囲が先頭約 750 万位までなので、始点で圏外だったサイトは「出現」しか見えず、出現前の順位は測れない、(3) 公開ごとの揺れが大きく、上昇か揺れかを一回の差で判別できない、による。2020 年より前の公開は範囲外で、より長い期間の再検証は未実施。
- 最大の限界: **公開ごとの順位の揺れが 1 桁以上**ある（例: ある小さな個人サイトで 43,743 位 → 368,483 位 → 67,386 位 → 549,897 位、kottke.org も 5,280〜355,509 位の間を往復）。クロールの範囲の違いによるもので、実力の変化ではない。running max にすると一度の外れ値が最高値として固定される。実装するなら 3 回分の中央値の running max など平滑化が必要。

## 3. Wayback CDX（A: 積み上げたページ数）

- 方法: `cdx/search/cdx?url=<ドメイン>&matchType=domain&collapse=urlkey&filter=statuscode:200&filter=mimetype:text/html&fl=timestamp&limit=30000`。`collapse=urlkey` で各 URL の最も古い保存だけが返るので、年ごとに数えて累計にする。
- 13 サイト中 **10 サイトで取得、3 サイトで失敗**（取得できたのは 1,228〜30,000 行、8〜87 秒。jvns.ca は別走行）。**gwern.net / kottke.org / righto.com は 503/504 で失敗**（3 回再試行、大きなサイトは 60 秒でゲートウェイが切る）。ページ分割（`page=`）は 1 ページ約 57 秒で、全体は実用的でない。レート制限に配慮し、1 リクエスト後に 3〜5 秒空けた。再現スクリプトでは 503/504 の再試行を 10 秒から倍々（上限 300 秒、最大 5 回）に広げた。
- 30,000 行で打ち切られたもの（hyuki.com、kmonos.net）は並びが URL 順のため、年ごとの累計は偏った標本になる（下限扱い）。
- 限界: 数字は「初めて保存された日」で、公開日ではない。保存の集中で段差が出る（kmonos.net は 2017 年に 28,764 件が一気に増えた）。大きなサイトは取れない／通信が不安定。サイトのドメイン単位のため共用ホスティングは対象外。
- 傾きの言葉: 直近 1 年の増加数 ÷ その前の 1 年の増加数（例: paulgraham.com は 2025 年 857 件、2024 年 645 件で約 1.3 倍のペース）。jvns.ca は 2024 年 724 件 → 2025 年 2,914 件（約 4 倍）だが、保存の集中の影響を受けうる。

## 5. 保存のスキーマ案と更新

```
site_attention(site_id, metric, observed_at, value)   -- 主キー(site_id, metric, observed_at)
  metric: 'wayback_pages_cum'（その時点の累計）, 'cc_best_rank'（その時点までの最高順位）
```
- **累計値＋観測時点**を 1 行ずつ追加するだけで、既存行は書き換えない（減らない）。
- 容量: 1 サイト・1 指標・四半期ごと 1 行で 年 8 行 ≈ 数百バイト。1 万サイトで年 8 万行、数十 MB 以下（D1 の上限 10GB に対して余裕）。
- 更新頻度: 公開が四半期ごとなので四半期 1 回。C は先頭 200MB × 1 回（約 200MB・10 秒）で全サイト分が一括で出る。A は 1 サイトずつ 10〜90 秒でレート制限があり、1 日あたり数十サイトまでに抑えた分散実行が現実的。
- 「早期発見」の見せ方: 保存した時点の値と今の値を並べるだけ（決定論）。

## 7. 再現方法（`scripts/attention/attention_probe.py`）

標準ライブラリのみ（グラフ作成だけ matplotlib）。生データは `var/attention/`（`.gitignore` 済み）に置き、コミットしない。UA は `MiseResearchBot/0.1 (+https://github.com/kako-jun/mise)` で、Common Crawl は 2 秒間隔、Wayback は 5 秒間隔、503/504 は 10 秒から倍々（上限 300 秒・最大 5 回）で再試行する。

```
# 順位ファイルの先頭 200MB を取得し(RANGE_MB で変更可。Range に 206 が返らなければ全体を読まず中止)、ドメインを引く
uv run python3 -I scripts/attention/attention_probe.py ranks cc-main-2026-aug-sep-oct cc-main-2025-sep-oct-nov
uv run python3 -I scripts/attention/attention_probe.py lookup paulgraham.com gwern.net elm-chan.org
# Wayback の初回保存日(年ごとの累計の元)
uv run python3 -I scripts/attention/attention_probe.py wayback jvns.ca elm-chan.org
# グラフ: rank_runmax.png(順位の生値と到達した最高順位。--vs の前が掲載サイト群、後が比較サイト群)と wayback_cum.png を var/attention/ に出力
uv run --with matplotlib python3 -I scripts/attention/attention_probe.py plot elm-chan.org --vs paulgraham.com gwern.net
```

docs/ideas/attention/ の 2 枚は、この `plot` で（10 公開分を取得・`lookup` 済みの状態から）再生成できる。

施設内プロキシ配下では、Python 3.13 の証明書検証が通らない場合に `MISE_RELAX_TLS_STRICT=1`（X509 strict だけを外す）と、`SSL_CERT_FILE` に CA バンドルを指定する。
